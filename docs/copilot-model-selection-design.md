# Copilot 模型选择功能设计

> 状态：三项产品决策已确认，已实现模型选择与对话边界切换。构建、测试和未登录页面检查通过；仍需用已授权的真实账号联调 `listModels()`、模型权限/计费元数据和实际对话切换。不实施多任务并行。

## 用户目标

用户希望按开发任务的复杂度选择 Copilot 模型：简单修改可以使用更合适的模型，架构设计、跨文件改动或复杂排障可以自行选择其他可用模型。选择应在提交任务前可见、任务运行时可修改且变更时点明确、任务运行后可追溯；不能因后台默认值变化而悄悄切换。模型可用性和实际计费取决于登录账号、组织策略及 Copilot 服务端，不提供未经验证的价格或效果保证。

## 用户体验

1. **新建任务**：在“需求与设计”区域增加“Copilot 模型”下拉选择，默认选中管理员 `COPILOT_MODEL` 指定的模型；未配置时为“自动选择”。下拉选项来自当前登录用户可用的模型列表，展示名称，以及有依据时的能力说明（例如“支持图片输入”）和计费倍率；不以“最快/最强/最便宜”给出无法保证的排名。模型 ID 可在详情或辅助提示中查看，不要求用户手输 ID。管理员默认模型对当前用户不可用时提示选择其他模型，不暗中回退。
2. **场景建议**：控件下方简短提示“日常修改可保持自动选择；复杂任务可指定模型”。选择显式模型后仅提示“本任务将使用此模型”；如果提供了设计图，仅能选择已确认支持视觉输入的模型，或明确告知用户需先移除图片。不能把文件附件支持与图片理解能力混为一谈。
3. **加载与异常**：模型列表加载中保留自动选项；获取失败时显示“暂时无法获取可用模型”，允许使用自动选项创建任务并提供重试按钮，不展示上次用户或其他账号的缓存结果。若管理员默认是显式模型且列表不可验证，则提示重试或由用户选择自动模式，不把显式模型当作已确认可用。登出或换账号时清空选项。组织禁用的模型显示禁用原因或不列入可选项，绝不以选中状态提交。
4. **任务详情与切换**：在“任务信息”中显示“当前模型”和“下次对话使用”，提供与新建任务一致的紧凑“更换模型”菜单。点击选项即保存为下次对话的目标模型，无需再点应用按钮；保存中暂时禁用菜单，失败则保留原选择并提示错误。当前对话仍使用原模型，立即显示“待当前对话结束后生效”；在未开始下一条消息前允许再次选择，以最后一次有效选择为准。新任务开始前或两次对话之间修改则在下一条消息生效。显示按对话划分的模型变更记录；自动模式仅展示“自动选择”，除非 SDK 明确报告最终模型 ID，不能猜测实际模型。
5. **继续与自测**：任务创建时的模型作为后续编码、自测生成和浏览器脚本生成的默认值；用户成功切换后，后续对话及后续新会话沿用新模型，包括补跑自测。等待用户回答属于当前尚未完成的对话，回答仍使用原模型，完成后才切换。在发布审批、失败或待验收等没有活跃对话的时刻可修改模型，供下次对话使用；已经开始的对话不受影响。

## 生效边界与状态规则

- 当前实现会在一次 `worker.execute` 中多次调用 SDK `session.sendAndWait`：编码一次、自测规划/修正若干次、每条浏览器用例可再调用一次。这里的“对话”定义为**一次发送开始到对应的 `sendAndWait` 完成**，包括期间工具调用及 `ask_user` 等待与回答；不是一次工具事件，也不是整个任务。任务在克隆/运行测试命令等非对话阶段收到切换时，下一次 Copilot 消息使用新模型。
- 已安装的 SDK 提供 `session.setModel(model)`，其说明为“下一条消息生效，保留会话历史”。切换请求到达时只持久化目标模型与修订号，不在进行中的消息内调用 `setModel`。当前 `sendAndWait` 结束后，worker 在**下一次发送前**读取最新目标并调用 `setModel`，成功后记录本次对话将使用的模型；如果当前执行已没有下一条消息，则后续新建会话时直接用保存的目标模型。不得用中断当前消息来模拟切换。
- 分开保存 `desiredModelId`（用户最后一次确认的目标）、`activeModelId`（当前/最近一次成功启动的对话使用的请求模型）以及 `pendingRevision`/`appliedRevision`。状态显示以服务端持久状态为准：执行中为“当前 X、下次 Y”；无活跃对话时为“下次使用 Y”，不能把待生效显示为已经生效。并发切换按任务版本有序处理，旧请求不得覆盖新选择。
- 模型权限或能力在切换后、下一条消息前变化时，`setModel` 或创建新会话失败，不发送下一条消息，也不自动恢复旧模型或自动模式；保留当前任务与工作目录，提示用户重新选择可用模型再继续。失败状态应能继续切换和重试，而不是将任务困在不可操作的执行态。重新认证后需要重新校验当前账号的权限。
- 历史记录至少包括提交人、提交时间、旧/新模型、目标对话序号、实际应用或失败时间；每次 Copilot 对话记录该条消息**请求使用的模型**。SDK 没有报告实际路由结果时，自动模式仍只记录 `auto`。用户切换不影响构建、测试、Git 审批流程，也不修改其他任务。

## 选择与费用边界

- “自动选择”沿用当前 SDK `model: 'auto'` 的行为，而不是平台自行按提示词估算复杂度或自行在候选模型间路由。`COPILOT_MODEL` 保留为管理员设定的**新任务默认值**；未设置时默认为 `auto`。创建时将最终选择保存到任务，之后修改环境变量不影响已有任务；用户在新建时及执行过程中均可主动改选。
- 每个用户只看到其当前登录身份返回的可用模型；以 SDK 返回的 `id` 作为内部值，名称只用于显示。策略为禁用或未配置的选项不允许提交；服务端在任务创建时重新校验 ID 和策略，不能信任前端列表。
- **费用展示仅使用 SDK 实际返回的 `billing.multiplier`**，标明“相对计费倍率（以账号实际规则为准）”；没有该数据就不展示价格。不估算金额、不把倍率当成确定的人民币金额，也不承诺自动模式最省成本。若需要实际费用上限或任务预算，另行设计账单数据来源和硬限额。
- 提供设计截图时，按 SDK 报告的视觉能力校验选择；能力信息缺失时不要声称支持，允许用户改为自动模式或等待可用模型数据。若自动模式运行时因输入能力不兼容失败，保留任务与附件并给出重选模型/重试路径，不静默丢弃设计图。

## 数据与接口草案

- `GET /api/copilot/models`：必须已登录，服务端用当前用户的凭据查询 SDK `listModels()`，仅返回必要的 ID、显示名、策略、视觉能力和可用计费倍率；响应禁止共享缓存并妥善处理 GitHub 认证过期、接口超时与限流。SDK 的 `listModels()` 在客户端连接后可调用且会缓存首次成功结果，因此服务端实例必须按用户隔离或确保缓存以用户身份为边界，不能把管理员的模型列表暴露给其他用户。
- `GET /api/copilot/models` 还需返回管理员默认模型 ID（或另设小型配置响应），使页面能显示正确默认值。若当前账号无权使用该默认模型，应标识不可用并要求用户改选，不把管理员配置当成全员授权。服务端使用同一规则验证显式模型和设计截图能力。
- `POST /api/tasks`：增加可选 `modelId`；缺省兼容老客户端，按 `COPILOT_MODEL || 'auto'` 解析一次，再存入任务。服务端只接受 `auto` 或当前用户可用的确切模型 ID，拒绝任意字符串、无权限模型及已知不支持上传设计图的模型；返回可操作的错误信息。验证应在写入任务和启动 worker 前完成，避免创建无法执行的任务。
- `PUT /api/tasks/:id/model`：仅所属用户且当前登录有效可调用，提交 `{ modelId, expectedRevision }`，校验候选模型与任务附件能力后原子更新 `desiredModelId` 和修订号，响应当前/目标模型及生效状态；版本冲突返回最新状态供前端重新确认。重复提交同一修订号不能生成多次切换记录。排队、运行、等待问答、审批、失败、待验收状态均可提交；已终结且不会再有对话的任务可保存“下次继续时使用”，但不能声称已应用。
- 任务持久化保存**创建时选择**和**最新目标/当前请求模型**、修订号及历史，不保存访问令牌；旧任务没有该字段时显示“历史任务：未记录模型”，继续执行前解析兼容默认并记录本次使用，避免将旧任务显示成用户主动选择了自动模式。任务摘要和详情对所属用户返回模型与待生效状态，日志按对话记录请求模型 ID、阶段和时间，不记录凭据。
- `server/execution/worker.ts` 每次创建 Copilot 会话时从任务记录读取目标模型，而不是再次读取当前环境变量；每次 `sendAndWait` 前检查目标修订号，仅在上一条消息结束后用 `session.setModel` 切换。这包括首次编码、失败后继续、推送确认/跳过后的自测、测试用例修正和浏览器脚本生成。SDK 因模型停用或权限变化拒绝启动或切换时，不自动降级至别的模型：保留任务、变更和错误提示，等待用户决定。

## 边界用例与验收

| 用例 | 预期结果 |
| --- | --- |
| 未登录、登录失效 | 不显示其他用户模型列表，要求重新登录后再查询 |
| 获取模型列表超时或失败 | 可以主动选择自动模式；显式管理员默认值未经校验不能提交，提示重试 |
| 用户选定模型后组织策略禁用 | 创建时拒绝并提示重新选择；已建任务在下一次会话启动失败时保留工作目录和待处理状态 |
| 有设计截图但显式模型不支持视觉输入 | 提交前阻止，明确指出冲突和可用替代项 |
| 创建后修改 `COPILOT_MODEL` | 原任务后续对话仍使用已保存的目标模型，除非用户主动切换 |
| 编码的 `sendAndWait` 进行中切换，随后调用 `ask_user` | 问答和当前对话使用旧模型；当前对话完成后的下一条 Copilot 消息使用新模型 |
| 自测规划/浏览器脚本连续发送时切换多次 | 当前消息不中断；下一条消息使用最后一次有效选择，历史与应用时点可查 |
| 编码结束，在推送审批期间改选再启动自测 | 没有活跃消息需等待；自测新会话使用新模型，不自动推送 |
| 模型被禁用、`setModel` 失败或 SDK 报错 | 下一条消息不得用旧模型继续，任务与工作区保留，可重新选择并恢复 |
| 任务失败后继续、手动补跑自测 | 使用最近一次确认的目标模型；等待用户回答时可以提交切换，但下一条消息才生效 |
| 自动模式执行 | 显示为自动选择；仅在 SDK 返回实际模型时记录实际模型，不杜撰计费 |

## 落地范围与联调

1. 已接入按当前 OAuth 凭据查询 SDK `listModels()` 的接口，并按账号验证显式模型与图片能力；仍需已授权账号验证实际返回的策略和计费元数据。
2. 已持久化任务模型、修订号与切换历史，编码、继续和自测的每条 Copilot 消息发送前检查目标，使用同会话 `setModel` 从下一条生效。单测覆盖当前消息未完成及切换失败不发送下一条消息；真实 SDK 会话交互仍需联调。
3. 已增加新建表单和任务详情的模型选择与当前/下次对话展示；需在登录状态下手动确认组织禁用模型、上传图片能力提示和动态切换反馈。

## 已确认的产品决策

1. 保留 `COPILOT_MODEL` 作为管理员设定的新任务默认值，用户可以主动选择其他可用模型。
2. 支持新建任务时选择，也支持执行过程中切换；正在执行的对话不中断，下一条对话才使用新模型。
3. 只展示 SDK 实际返回的相对计费倍率，不估算具体金额。
