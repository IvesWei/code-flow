| 类型 | 问题 |

| 优先级 | 待确认 |
| 所属功能 | 编码过程 / 变更文件展示 |
| 问题现象 | 当前编码过程中的变更文件展示不及时。 |
| 期望行为 | 每次编码产生文件变更后，实时展示并更新当前任务的变更文件汇总，而非等待整个编码阶段结束。 |
| 影响 | 用户难以及时了解编码期间已改动的文件与当前变更进展。 |
| 复现步骤与证据 | 待补充具体任务、操作步骤及截图或时间记录。 |
| 根因 | 待排查，不预设前端刷新或后端汇总为原因。 |
| 待确认事项 | “每次编码后”的触发边界（单次文件编辑、工具调用完成或模型一轮结束）；实时更新的可接受时延。 |

### 验收标准（待实施时确认）

- 编码尚未结束时，已产生的文件变更能够按约定的触发边界与时延更新到汇总中。
- 后续编码继续改动文件时，汇总反映当前实际变更，不停留在旧结果。
- 不需要手动刷新页面才能看到上述更新。
- 汇总限定在当前任务工作目录内，不混入其他任务的文件。

## OPT-002 优化任务接口全量返回与频繁请求的性能

| 字段 | 内容 |
| --- | --- |
| 记录日期 | 2026-10-10 |
| 类型 | 优化项 |
| 状态 | 待处理（用户反馈，尚未开展性能测量或实施） |
| 优先级 | 待确认 |
| 所属功能 | 任务查询接口 / 前端任务更新 |
| 优化诉求 | 当前一个后端接口返回所有任务的信息，并被频繁请求；任务数量较多时，全量返回可能导致响应较慢，需考虑优化方案。 |
| 期望行为 | 只获取当前视图所需的任务与字段，避免频繁重复传输全部任务信息，同时保持任务状态和执行进展及时更新。 |
| 影响 | 随任务数量和单任务记录增长，可能增加服务端处理与序列化、网络传输及前端解析和渲染开销。具体瓶颈待测量。 |
| 关联项 | ISSUE-001：优化请求机制时，应同时考虑变更文件汇总的及时更新，不能以降低更新频率掩盖性能问题。 |
| 待确认事项 | 实际请求频率、任务数量与单任务数据量；列表与详情所需字段；可接受更新时延；响应耗时及大小目标；是否需要筛选、排序与历史任务分页。 |

### 待评估方向（非已确定方案）

- 任务列表分页或游标加载，并仅返回列表摘要；选中任务按需请求详情，日志和测试证据可单独按需加载。
- 使用版本号、条件请求或增量查询，避免重复返回未变化的数据，并处理更新顺序与漏更新。
- 根据活动任务、当前视图及页面可见性调整轮询范围与频率；评估 SSE 等推送机制及断线恢复方式。
- 根据测量结果评估查询、缓存和索引优化，不预设数据库为主要瓶颈。

### 验收标准（待实施时确认）

- 高频更新不再依赖反复返回全部任务的完整信息，列表响应范围与大小受到控制。
- 当前任务的状态、执行记录及文件变更仍能在约定时延内更新，不出现漏更新或旧结果覆盖新结果。
- 历史任务仍可完整查询；分页、筛选或增量更新不造成任务遗漏或重复展示。
- 在约定的任务规模下记录优化前后的响应耗时、响应大小和请求量，并达到确认的性能目标。
- 保持任务归属与访问权限隔离，不因分页、缓存或推送暴露其他用户的数据。

### 处理记录

- 2026-10-10：登记第三项用户反馈；仅记录诉求与待评估方向，未修改接口或实施性能优化。

## ISSUE-002 确认任务后台执行与关闭页面的独立性

| 字段 | 内容 |
| --- | --- |
| 记录日期 | 2026-10-10 |
| 类型 | 问题 |
| 状态 | 待确认（尚未核实当前执行形式或复现关闭页面的影响） |
| 优先级 | 待确认 |
| 所属功能 | 任务执行 / 后台生命周期 |
| 用户要求 | 任务应在后台执行，即使用户关闭页面也不会影响任务进行；需具体确认当前任务的执行形式。 |
| 期望行为 | 后台已接受并启动的任务独立于浏览器页面执行，关闭页面、刷新或浏览器连接断开不会取消任务；重新打开后可查看最新状态与结果。 |
| 风险与影响 | 若执行依赖页面连接或前端生命周期，离开页面可能造成中断或进度丢失。是否存在该问题尚未验证。 |
| 关联项 | OPT-002：前端轮询或推送仅用于观察状态，不应成为后台任务持续执行的条件。 |
| 待确认事项 | 当前执行由浏览器、HTTP 请求、API 进程内异步 worker 还是独立 worker/队列承载；请求断开、页面关闭和登录失效是否影响已启动任务；实际停止与恢复条件。 |

### 后续核实范围

- 检查任务启动、请求结束与取消逻辑，确认任务是否绑定请求或浏览器连接，记录负责执行的进程及其生命周期。
- 对已启动任务分别验证关闭标签页、刷新、关闭浏览器和网络断开，使用后台记录与实际执行证据确认是否继续。
- 重新打开页面后，检查能否读取持续执行的进度、日志和最终结果，不重复启动同一任务。
- 单独确认后台停止、重启及机器关机后的中断与恢复策略；这些不等同于关闭页面，本项不默认要求任务跨进程自动续跑。
- 明确需要回答业务问题、确认推送或其他用户审批时的等待行为：页面关闭后可继续保持等待，不得自行替用户确认。

### 验收标准（待核实后确认）

- 后台接受并启动的任务在关闭页面或浏览器连接断开后继续执行，除非遇到原有审批等待、失败或明确的取消条件。
- 停止前端轮询或推送连接不会停止后台任务。
- 重新进入任务后可查看最新状态与执行结果，不丢失记录、不重复执行任务。
- 等待用户确认的任务重新打开后仍可识别并处理待办，关闭页面不视为同意、拒绝或取消。
- 明确记录后台进程停止及重启的处理边界，不把对话恢复等同于执行进程持续运行。
