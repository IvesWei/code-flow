# PRD 内容组织

## 新生成 PRD：固定双模板

新双模板修订保留完整 `templateVersion: 2` PRD，另外在同一修订保存 `businessReview` 业务变更清单。普通评审可切换两版，切换和导出都不启动模型、不写项目。没有 `templateVersion` 的旧 PRD 仍用原有展示及单份 Word，不迁移。

业务版按所属模块、功能只列本期用户操作、可见结果或后台逻辑的增删改。每条描述带中文种类和颜色；范围不明确的单列为“待核对”。后台逻辑只写触发条件和结果，不配图；界面变更只选能说明该条的本修订目标状态，没有对应图就显示“待补图”。同一图在正文中首次插入，后续只引用。既有行为、防回归状态不因共用功能或验收 ID 进入业务版。例如新增硬件处理分支时，可以选操作、必填说明和新增终态画面；不因为普通分支或原有标签切换也需要验收，就把它们列为业务改动。

业务宽屏以全屏模糊遮罩呈现，桌面左侧设计、右侧标注，用虚线分隔。点选或阅读标注联动目标图；选中同一功能内的后台规则也会清空设计。右上角关闭或按 Escape 均返回原入口。小屏用“设计 / PRD”切换。开发规格版不经过清单过滤：仍按完整功能大纲保留场景、行为、字段及枚举、状态流转、全量设计映射、规则、异常、权限及 Given/When/Then。

新 PRD 编写后由需求角色另开无工具文本会话整理；目标原型生成或调整经静态检查后，以新状态 ID 重选图，不改已有变更文字。平台核对逐字 PRD 引文、功能与图片归属及修订版本；不自动证明模型对业务差异的理解正确。自动整理失败不撤销可用的完整稿；保留已有文字时清空过期选图。未整理的双模板修订明确提示“尚未整理”，不回退到全量正文。对当前有效修订可显式点击“整理业务变更”（`POST /:id/jobs`，提交 `version`、`stage: "business-review"` 和 `revisionId`）；历史只读，不批量回填。此作业不增加修订、不重做 PRD/画板、不改变审批。

生成提示词按文风规范要求先拆分原子信息，再将行为、字段属性、校验条件、计算口径、异常和权限分配到唯一归属处，输出前逐功能及跨功能自查去重。行为使用正向动作短句，规则使用名词短语；删除防御性穷举、过程描述和同义反复，开发版规则增量不复述业务描述。单条以 1–2 句、50 字以内为宜，超过 80 字要求拆分或精简；系统行为以 3–6 条为参考，简单功能不凑条数，超过 8 条优先下沉非行为信息。此为模型生成要求，不对历史文本做机械截断、去重或迁移，不改变现有结构、数据契约、页面和导出。

`requirements[].specification` 保存各功能的字段规格、状态流转、规则、异常、权限及验收映射。生成、编辑和持久化共同校验编号唯一性、字段顺序、验收结果与内部映射一致性、关联编号有效性及未知权限不得默认放行。新模板不能通过 JSON 编辑降级；内部需求/验收 ID 继续用于原型关联，旧修订不受影响。JSON/MySQL 沿用修订 JSON，无需数据库迁移。

“导出 PRD”对新模板下载一个 ZIP，且仅含 `业务评审版.docx` 和 `开发规格版.docx`。业务 Word 与网页共用变更清单、文字色和图片归属；未整理时仅提示，不冒充已筛选。开发 Word 仍在各功能下插入映射的全部状态图，包括共享图。使用 `GET /:id/exports?format=zip&scope=prd&revision=...` 按所有权及修订读取图片，保持原始比例；完整开发导出所需截图丢失或损坏时仍报错，不启动模型。原有非 PRD 专用导出 API 不变。

## 旧 PRD：兼容展示与导出

审阅模式的弹窗左边缘提供默认隐藏的 PRD 目录抽屉，鼠标悬停左侧空白边缘滑出，移出目录区域向左收起。目录按正文的模块、页面和功能分组，点击节点仅滚动 PRD 面板至对应内容，不挤压分栏或滚动背景。边缘目录图标支持点击与键盘打开，Escape 先关闭目录并恢复焦点，不关闭弹窗；隐藏抽屉不可进入键盘焦点。小屏目录宽度限制在视口内，支持长目录独立滚动，并遵循减少动态效果设置。普通非弹窗评审不展示抽屉。

评审区提供“宽屏评审”入口，弹窗标题为“审阅模式”，标题左对齐，设计区域宽度滑杆在同一行居中，右侧为 28px 关闭按钮。桌面左侧展示 PRD、右侧展示设计稿，滑杆表示右侧设计稿的占比，默认 56%。弹窗高度为视口减 64px、最高 900px；移动端高度为视口减 48px，保留设计/PRD 视图切换。弹窗外层不滚动，头部固定，长 PRD 和设计稿只在各自面板内滚动，避免面板与弹窗形成嵌套滚动。弹窗支持关闭按钮和 Escape，关闭后焦点返回入口；下拉菜单在弹窗内展开，背景页面在审阅期间不可操作。

“设计区域宽度”所在行右侧提供“导出 PRD”，普通评审和宽屏审阅均可使用。导出选中修订的 Word（.docx）文档，正文与页面 PRD 共用模块分组和多行文本拆分规则，保持标题/概述、模块、功能名称、对应场景、功能描述、嵌套字段和页面说明的顺序及内容。保留“未分组功能”“其他功能”，页面说明中的字段表按页面相同的嵌套列表展示；不额外插入页面未展示的完成标准、内部映射 ID 或来源记录。每个功能描述之后直接插入关联的全部原型状态截图，并标注页面和状态；同一设计稿关联多个功能时在每个对应功能下展示，不再集中到文末。无法关联有效功能的设计稿会阻止导出并提示修正，不猜测归属或静默遗漏。不包含澄清记录、运行日志、验证明细、源码或打包清单，讨论稿/静态交互未验证标识保留在页脚。历史修订按所选版本导出，不混用最新截图。截图缺失、文件丢失或完整性检查失败时停止导出并提示，不自动运行模型或重新截图。按钮显示导出状态和错误，失败时不离开审阅弹窗；完成后可关闭提示，焦点返回导出按钮。复用所有权鉴权的 `GET /:id/exports?format=docx&scope=prd&revision=...`；未指定 `scope` 的原有 MD/DOCX/HTML/ZIP 导出保持不变。

PRD 评审采用嵌套列表大纲，对齐需求截图：“模块”加粗，其下逐功能展示“功能名称 / 对应场景 / 功能描述”。功能描述中的行为规则逐条列出，字段名在下一层，字段规则、选项在再下一层，选项各占一条，不以逗号拼接。没有明确场景时显示 `--`，不根据页面标题推断业务场景。完成标准保留在数据和导出中，不在阅读正文展示；页面说明及历史页面表格折叠保留，不再作为主体页面标题打断大纲。内部需求 ID、验收 ID 和设计区域映射保留，但正文不展示编号。

结构兼容可选 `blocks[].module`、`requirements[].scenario` 和 `requirements[].fields`（包含 `name`、`description`）。功能描述与字段说明使用换行分隔条目。级联选页与 PRD 使用相同模块名称。旧章节缺少模块时归入“未分组功能”，未关联章节的历史功能保留在“其他功能”；不根据旧自由文本臆造模块或字段。原有表格在前端折叠的页面说明内按行转为嵌套列表保留全部内容，导出仍保留原表格，并包含模块、场景和字段内容。修改生成规范不会自动重新生成或修改任何真实项目。

影响用户可见内容、操作能力或结果的角色权限、数据范围、删除限制、重复和部分失败处理仍属于 PRD，放在受影响功能下。接口、数据库、鉴权实现、事务、队列、部署等技术细节留给后续技术方案，不在本次自动生成技术方案。来源证据和澄清记录保留为追溯信息，不进入主体叙述。

前端和导出均按所属章节展示功能，完成标准仅保留在导出中，同一功能仅在首个关联章节完整展示。来源在界面折叠、导出放入附录。已有版本仅调整展示分组，不改写原文、不删除历史权限或技术内容；需要新的内容结构时由用户显式生成新 PRD 并重新确认，旧版本和设计记录不自动迁移。

# 需求与设计工作区

## 任务详情功能分区

详情顶部集中展示项目概况、四阶段进度及当前主要操作，其余入口收纳到“全部阶段操作”。阶段条仅展示状态，不支持跳过原有前置校验。运行进度、取消任务、人工登录、错误、取证待补充和未回答问题的处理入口始终保留在分区外。

内容划分为“用户输入与证据”“系统产物”“澄清与决策”“任务记录”：原始文件、链接、代码快照及取证地址与系统提取的证据摘要分开；现有页面基线标注所选修订。系统产物集中展示修订历史、PRD 双版本、原型、静态检查、导出与修订意见。待回答问题和已确认决策独立归档，阶段任务与进度时间线分栏。

待澄清问题一次只显示一条，显示当前题号与已填写数量，支持上一条、下一条及返回修改。点击选项或用空格/Enter 确认后自动进入下一条，最后一条停留，不自动提交。方向键仍可在当前题的选项间浏览；手动文本输入不自动翻题。推荐答案只在对应选项末尾显示“【推荐】”，不再额外重复建议文字。各题答案在切题、切换分区及刷新后继续沿用原有草稿暂存；提交仍一次提交所有已填写答案，允许部分提交。

耗时操作提交后立即在对应区域显示执行中提示，而不只是禁用控件。本地/远程代码快照按钮显示加载状态，读取和保存期间保留说明，完成后就地提示成功，失败时保留输入并显示错误供重试。资料上传、链接读取、取证配置、答案提交、PRD 保存、修订创建及阶段请求同样提供区域内反馈。后台分析、PRD、设计与静态检查在顶部及相关资料/产物/记录区域展示真实任务进度；等待人工登录时明确显示待处理，不伪造百分比，不将“请求已提交”等同于“任务已完成”。切换分区不会中止执行或丢失反馈，刷新后后台任务继续从服务端状态恢复；普通 HTTP 请求仍遵循原有页面生命周期，不增加持久化或自动重放。加载图标遵循减少动态效果设置，状态使用可访问播报，既有错误与取消入口保持不变。

有修订时默认展示系统产物，无修订时默认展示用户输入。分区支持方向键及 Home/End 导航；切换不会卸载表单或清空草稿、原型选择和评审位置，未保存的 PRD 编辑需确认后才能暂时离开。窄屏采用单列与两列分区导航，保留 PRD/设计视图切换。设计区域默认宽度调整为 56%，滑杆仍支持 35%–70%，宽屏评审的目录、独立滚动与焦点恢复不变。接口、数据、确认门禁及静态验证范围不变。

## 当前实现

入口为功能菜单“需求与设计”，路由 `/requirements` 和 `/requirements/:projectId`。
已接入项目、附件和公开链接、分轮澄清、结构化 PRD 编辑与确认、设计生成、左右关联、修订历史、静态截图验证及 MD/DOCX/HTML/ZIP 导出。
模型阶段使用受管 PRD skills 和本地 ui-ux-pro-max；输入附件直接交给 Copilot，仅允许受控快照工作区工具，链接由平台受控读取。
安全边界、持久化和生成门禁位于服务端，不依赖前端按钮禁用。

请求中的 CAS 字段统一为 `version`；HTTP 层转换为服务内部的 `expectedVersion`。
修改来源、分析阶段的答案或修订意见后需重新分析；仅回答 PRD 阶段的澄清问题保留有效分析，全部回答后可点击“继续生成 PRD”。新答案使旧 PRD/设计失效，必须重新生成并确认 PRD 才能设计。PRD 未确认不能生成正式设计。
页面离开不取消任务；重启将未完成作业标为 interrupted，取消后的迟到结果不会覆盖项目。

## PRD 撰稿失败后如何继续

1. 在项目概况点“继续生成 PRD”。打开或刷新项目不会启动作业。该操作保留有效分析与已保存的澄清答案；只有紧邻的上一个作业是失败或中断的 PRD 时，才尝试从它的撰稿记录恢复。
2. 在“任务记录”查看实际采用的路径。输入与取证匹配时，若仅保存了取证依据，就直接撰稿；若还保存了候选稿，就校验该稿，只修可定位的错误，不再起草全文。真实截图必须重新核验文件归属及哈希，源码降级仍明确标记未验证真实运行态。不匹配的输入按当前资料重新生成。
3. 要主动放弃候选稿，可在“全部阶段操作”选“重新取证并生成 PRD”（无取证地址时为“从头撰写 PRD”）；取证类错误也可用“取证待补充”中的同名操作。此请求在 `POST /:id/jobs` 的 `version`、`stage: "prd"` 外显式传 `restartPrd: true`，跳过撰稿检查点和旧截图；分类和入口映射仍按当前输入核验，不清空澄清答案、不重新执行分析。

字段修正仅覆盖双模板中可定位的 `specification.fields[].options` 与 `specification.criteria[].refs`。任务记录分批列出字段路径与原因。模型最多提交一次无工具补丁；平台只合并指定路径，拒绝整稿、额外或遗漏路径，并重新检查完整 PRD、引用及适用的取证字段覆盖。无固定选项的文本等字段可以是 `[]`；选择型字段没有已知枚举时，须说明动态来源或标记“选项来源待确认”，不凭空补选项。结构通过不代表业务选项已由人核实。无法局部修的既有候选不自动重写；只有通过完整校验的稿件进入人工评审，不自动确认。

新版检查点绑定项目与模型、资料（包括本次读取的链接内容）、需求、决定、当前修订、取证配置及撰稿策略。旧作业没有此检查点时，仅尝试兼容有完整撰稿审计、来源与映射能逐项核实、且平台明确记录过源码降级的失败 PRD；不从工具输出或残缺回复推测候选。恢复使用新作业、新模型会话，不续活旧 SDK 会话，也不承诺固定耗时。

## Copilot 输入输出审计

需求分析、PRD、设计及原型调整使用相同的服务端会话审计。记录按项目、任务 `job_id`、会话 `conversation_id` 和递增 `sequence` 关联。UI 调整按稳定原型绑定同一个 `conversation_id` 与 SDK 会话，可跨多个任务；同任务中的恢复及重试仍连续编号，不会重复主键。`sequence`、`request_index` 按任务及会话组合递增；跨任务查看同一原型历史时按任务时间和轮次排序。

MySQL 使用独立追加表 `codeflow_requirement_conversation_events`，不把完整提示词或失败 HTML 塞进项目 `body`，不增加前端详情页，也不向项目列表或任务日志返回这些内容。上线前执行更新后的 `sql/mysql-requirements-schema.sql`；启动时只验证表是否可用，不自动执行 DDL。MySQL 写入失败不会回退到 JSON。显式使用 JSON 测试后端时，记录保存在 `requirements/conversations/<project>/<job>/<conversation>.jsonl`。

记录内容：

- `session.start`：实际模型 ID、完整应用系统消息、注册工具定义、权限摘要、项目版本和来源指纹；UI 调整另记录目标原型、策略版本及是否恢复。`session.created` / `session.resumed` 记录实际创建或恢复的 SDK 会话 ID。
- `request`：每次实际组装的完整用户提示词，包括 skill 正文、设计检索结果、确认的 PRD、调整指令、原型 HTML、失败候选及反馈；记录请求中附件的名称、SHA-256、大小和引用 ID。
- `attachment.chunk`：附件原始字节以分块 Base64 保存，每块 256 KiB，可按附件 ID 和 `chunkIndex` 重建；同一审计记录段中的相同附件不重复保存。恢复后因上下文变化或 SDK 压缩而重传的附件在新记录段独立保存，临时路径不作为可恢复依据。
- `request.accepted`：SDK 接收请求后返回的请求 ID；只有 `request` 而没有对应接收记录，表示不能证明该请求已被 SDK 接收。
- `prd.checkpoint`：撰稿前取证依据及可选候选稿（最多 2,000,000 字符）。仅服务端按属主、项目、作业读取；既不成为正式修订，也不在项目详情或普通日志返回候选正文。复用现有审计存储，无新增表或 DDL。
- `assistant.message`、工具开始/完成/部分结果、公开用量和上下文压缩/截断事件：保留实际应用层内容。取消或失败时，已收到但尚未形成完整消息的文本记录为 `assistant.partial`。
- `session.finish`：本次会话成功、失败或取消，以及安全的错误分类。这里的成功只表示模型会话阶段完成；浏览器校验和整个任务是否成功仍以任务状态为准。进程意外退出可能没有结束事件，应结合任务的 interrupted 状态识别不完整记录。

不保存认证配置、登录 Token、Cookie、密码字段或隐藏推理；已知认证 Token 在文本中被替换为 `[REDACTED]`。这些记录仍可能包含需求全文、代码和设计稿，属于受保护的业务资料，只应由授权数据库账户访问，不能写入普通控制台日志或提交到 Git。记录是应用发送的系统配置、请求和 SDK 可见事件，不声称是 Copilot 服务内部最终展开后的供应商请求或隐藏上下文。

输入及附件先成功写库再发送；输出和结束记录写库失败会停止任务，不保存成功修订，也不触发额外模型重试。单条 JSON 正文上限 16 MiB，超限明确失败，不静默截断；数据库 `max_allowed_packet` 必须足以容纳单条记录。记录默认长期保留，不自动清理，历史任务的原始提示词不能通过本功能补回。

按任务查看记录：

```sql
SELECT conversation_id, sdk_session_id, sequence, request_index, created_at, kind, body
FROM codeflow_requirement_conversation_events
WHERE owner_id = ? AND project_id = ? AND job_id = ?
ORDER BY conversation_id, sequence;
```

系统消息位于 `session.start` 的 `body.systemMessage`，完整提示词位于 `request` 的 `body.prompt`，模型文本位于 `assistant.message` 的 `body.content`。先按会话分组，再依次核对请求、工具返回、模型回答和结束状态；不要把进度日志中的基础提示词长度当作实际完整请求长度。

## 基于已有项目迭代

在项目的“需求资料”区域选择本地已有项目目录，检查候选代码清单后点击“添加代码快照”。选择目录不会自动上传；仅提交去掉根目录后的相对路径和筛选代码，不提交本地绝对路径，不读取服务端任意目录。新建项目先填写本次新增或优化的目标，再补充代码来源；纯新建需求不必提供代码。

也可在“远程仓库代码”填写仓库地址、可选分支和相对模块目录，点击“拉取代码快照”。地址直接复用编码工作流校验：支持 `https://github.com/owner/repo` 与 `http(s)://code.sunmi.com/owner/repo`，可带 `.git` 或末尾斜杠；拒绝地址中的用户名、密码、端口、查询参数和片段。分支留空读取默认分支；模块目录留空按仓库范围筛选，较大仓库应指定相关目录。

创建时先把仓库地址、分支和目录保存为项目配置，再分别保存取证地址、资料和远程快照。快照失败时，详情仍会在“用户输入与证据”中显示配置并预填拉取表单，但不会增加原始资料。报错区分所选分支或目录没有文件、文件类型或路径不符合规则、以及内容未通过安全校验。系统地址显示在项目概况和“现有系统取证”；旧快照通过完整性验证后可读出已有来源记录，无需重新拉取。

远程拉取在临时目录浅克隆，不 checkout、不执行仓库代码、不读取子模块或 LFS 内容。读取 API 服务运行账户的本机 Git 全局/系统配置和已配置的凭据助手，允许使用已有仓库凭据；不弹出交互登录，不转发 Copilot 登录令牌，不继承代理环境或任意 Git 环境覆盖。凭据助手是本机可信程序，服务端需要事先配置好仓库访问权限；需要交互登录的仓库仍会失败，可继续使用已授权的本地目录上传。不会降低 TLS 校验或向链接追加 token。服务端须能访问对应主机，内网地址在外部部署环境可能不可达；HTTP 地址可能明文传输凭据，应优先 HTTPS，仅在可信网络中使用 HTTP。

快照记录规范化仓库地址、实际 commit、请求分支、模块目录和排除数量；路径保持仓库根相对形式。拉取超时为 60 秒，整个读取操作上限 90 秒，临时克隆数据按 256 MiB 巡检并在结束后复核、清理；巡检不是硬传输限额，瞬时可能超量。取消、超时或 Git 输出超限会终止进程树并等待退出，再清理临时目录；退出与清理可能使请求结束略晚于读取时限。认证、分支、证书和容量等已识别错误显示安全的修复提示，不返回原始 Git 输出；清理异常单独记录，不覆盖原始读取错误。拉取后仍受下述快照限制，超限不保存部分结果；模块目录只限制读取范围，不减少浅克隆本身的大小。每次点击都会显式获取新快照并要求重新分析，不在后台自动同步。

本地上传快照最多 200 个文件、单文件 128 KiB、累计原始 UTF-8 1 MiB。远程快照支持最多 2,000 个文件、单文件 512 KiB、累计原始 UTF-8 8 MiB，加入行号与来源说明后仍不得超过单份资料 10 MiB。容量超限拒绝整批，不按文件顺序静默截断；较大项目仍建议选择与本次需求相关的模块目录，避免无关内容占用模型上下文。这些字节限制不保证模型完整理解所有文件。

隐藏目录、依赖、构建产物、锁文件、常见敏感路径和不支持的文件类型会排除，服务端还会独立复核路径、重复项、大小、文本和明显凭据。远程读取时，未通过内容安全检查的文件不保留内容，并在快照来源说明中记录排除路径及读取局限；其余安全文件可正常导入。全部文件都未通过检查时拒绝导入。本地上传仍拒绝含不安全内容的整批资料。过滤可能保守误判，也不是完整秘密扫描；提交前仍需检查代码，模型不得臆测被排除文件的实现。

正文已取消按 password/token/secret/authorization 等字段名、赋值和 XML 标签泛化排除整份组件的规则；变量引用、类型声明、普通权限枚举及模板绑定可原样进入快照。仍拦截明确的私钥标记、已识别提供商 Token 格式和带用户名/密码的 URL；路径、字节限制及文本完整性检查不变。这不是完整凭据检测，提交前必须自行清理真实秘密。已有快照不会自动补回被排除的正文：需重新拉取/上传相关代码快照并重新分析，再继续生成 PRD；不自动重放真实任务。

平台将代码保存为带相对路径、SHA-256 和行号的只读来源 `existing-project-code.md`，按原有来源所有权与哈希校验读取，不执行、安装或运行项目。每次分析、PRD 或设计创建独立临时工作空间，将验证后的快照放入 `sources/snapshot-N.md`，其他附件复制到空间内再提交；SDK 会话数据存放在空间之外。会话结束、失败或取消后清理整个临时目录，不修改原始资料或现有项目目录。

模型输入的 `codeSnapshots` 只包含来源 ID、登记路径、大小、行数及有长度限制的来源/排除说明，不内联整份代码。模型通过 `workspace_list`、`workspace_search`、`workspace_read` 按需检索和分段读取；通过 `workspace_write_notes` 创建或替换 `notes/*.md` 临时笔记，不能改写快照。工具只接受已登记来源与规定笔记路径，拒绝绝对路径、目录穿越、符号链接及其他文件；原生终端、任意文件读写、网络和秘密读取权限仍拒绝。这是应用层能力隔离，不是容器或操作系统级沙箱。来源正文仍是带编号代码的 Markdown，而不是可执行的检出项目；引用时使用正文中的原始文件路径/行号，不能把工具返回的快照行号当作代码行号。

初始序列化提示上限为 2,000,000 字符；单次工具结果上限 24,000 字符、累计 500,000 字符、最多 128 次调用。读取每次最多 200 行，超长行可用单行读取及 `characterOffset` 继续；搜索采用字面量匹配并返回分页和截断信息。笔记单份最多 64 KiB、最多 32 份、合计 256 KiB，并行操作串行执行以维护配额。日志只记录工具名、调用与返回量，不记录正文。模型必须报告未读、被排除和超出预算的范围，不能据此声称完整检查仓库；这些限额仍不保证所选模型的实际上下文容量或分析质量。

分析、PRD 和设计均使用保存的同一份快照，但各自创建新的临时工作空间，笔记不跨会话保留：分析阶段沿“路由配置 → 绑定的 Layout 壳子 → 菜单层级 → 页面父容器 → 目标组件与屏位”沉淀经快照路径核验的结构化 `sourceAnchors`，下游 PRD 与设计直接消费这些壳子与文件锚点，避免重复泛搜仓库；PRD 阶段在启动真实浏览器取证或等待人工登录前先结束预检子会话，取证完成后以干净的编写子会话生成双模板 PRD，避免排错对话污染上下文或空占会话；UI 设计支持 `incremental`（绑定 `sourceAnchor` 锁定真实 Layout 壳子与非改动存量区域）与 `redesign` 双模式，状态支持声明 `proves` 与精准截图策略（`viewport` + `scrollTo` 中下屏聚焦、`element` 弹窗特写、`fullPage` 长图），并在整份设计首次生成时自动执行隔离 Chrome 截图校验及最多一次视觉失败自愈重试。没有代码证据时不得声称已检查现有项目。

添加快照会使原分析失效，必须重新分析后再生成、确认当前 PRD 和设计。原目录后续修改不会自动同步；需要显式添加新的快照并重新分析。现有历史修订不被改写，JSON/MySQL 沿用现有来源结构，无需新增数据库表或自动迁移。代码快照属于模型输入，会发送给所选 Copilot 模型，须确保具有提交权限。

### 原型对话调整
UI 调整在读取受管 PRD skills 之前独立分流，不携带 PRD 模板、写作规范、分析阶段契约、全项目描述/证据/澄清历史、无关附件或源码快照。首轮仅传递：当前目标共享原型及全部状态、这些状态关联的 PRD 需求/字段/验收与必要章节、按分类选择的原页面参考、ui-ux-pro-max 工作流、用户本轮原文。系统另保留静态 HTML 安全、唯一原型 JSON、状态和需求映射约束。共享 HTML 只提供一次，不重复派生状态的完整 HTML；旧独立屏幕仅在首次转换时作为转换输入。

目标 PRD 通过全部状态的需求映射并集裁剪，不按标题模糊匹配，不遗漏相关字段和验收。独立新增区块不携带原页面；已有区块只携带对应已验证基线的原始截图、路径、采集时间和结构，并明确说明它是“需求改动前的平台原页面”，不是当前原型或目标设计。混合范围逐区块处理。缺少明确分类的历史原型报 `DESIGN_ADJUSTMENT_SCOPE`；已有范围缺图或基线过期报 `PAGE_CAPTURE_BASELINE`，不得猜测成新增、自动补拍生产页面或回退整份 PRD。需先通过原流程生成并确认分类完整的 PRD，不自动迁移真实历史项目。

加载 `.github/prompts/ui-ux-pro-max.prompt.md` 的真实工作流，模型按本次页面类型和调整意图调用只读 `ui_ux_search`，选择 ux/style/color/typography/chart/icons/web 或 html-tailwind 布局建议。工具执行随项目分发的本地 Python 检索，最多 8 次，不联网、不安装、不写设计系统文件，也不开放通用 Shell。静态 HTML 不能引入 Tailwind 或外部字体/运行库。品牌和未涉及组件保留，但用户要求改善的布局、间距、密度与视觉层级不再被通用样式锁冻结。

每个原型首次调整建立一次干净专属会话，项目 `prototypeConversations` 保存绑定和上下文指纹，沿用现有项目 JSON/MySQL body，无需新增表或 DDL。SDK 历史保存于 `<DATA_DIR>/requirements/prototype-sessions/<owner>/<project>/<conversation>/`，结束时只断开，不删除历史。下一次调整及浏览器重试通过 `resumeSession` 恢复同一个 SDK 会话，并关闭旧待执行工作的自动续跑。目录和会话 ID 同时是恢复前提；`PROTOTYPE_SESSION_RESTORE` 明确停止，不静默开替代会话。已清理的旧临时会话不能补回，上线后首次进入此通道建立新会话，之后持续复用。备份时需同时保存数据库和此历史目录；本地历史也是受保护业务资料，不能提交 Git。

后续消息只追加用户本轮输入、当前状态 ID/映射及权威版本标识；相关 PRD、原页面、skill 或原型确有变化时才补充相应内容。检测到 SDK 历史压缩或截断后，下一轮重新补齐必要上下文，仍复用原会话，不假设完整 HTML 永远驻留。失败候选已在同一会话中时不重复传整份 HTML。当前已保存原型是权威；新调整不得自动继承被拒绝/取消的候选。状态 ID 更新和旧屏幕转共享原型不会新建会话；重新生成整份设计则开始新的原型会话谱系，避免相同模型页面 ID 串历史。SDK 可能压缩历史，不保证无限上下文或审美质量。

调整输出的需求映射错误，以及缺失/重复状态节点、节点标记绑定到不受支持的元素、重复操作和不兼容的文本/字段目标，每个任务最多允许在同一模型会话中纠正一次，浏览器重试不能重置此预算。纠正期间禁用工具，仍须完整通过原有契约与静态检查，不自动补造映射或删减状态。安全违规、未知字段、超限和其他错误直接失败；纠正再次失败也立即停止。共享源校验使用固定错误分类，避免将结构错误统一隐藏成 output contract violation。失败候选 HTML 和结构化检查报告不写入项目修订，公开输入输出保留在审计记录中。

原型调整的浏览器静态检查首次失败时，在同一任务中最多自动重试一次：恢复同一原型会话，追加原修改意见、失败状态、视口尺寸及具体映射/布局/截图错误；仅在会话尚无候选时补充失败 HTML，让模型基于候选纠正，再完整执行契约检查和静态截图检查。反馈中的状态 ID 还原为原稿状态 ID，不使用截图临时生成的新 ID；模型须保留原状态、映射和已确认 PRD，不得隐藏证据或删改范围通过检查。事件显示“自动重试 1/1”，不保存候选 HTML 或浏览器原始异常。第二次静态检查仍失败即停止并保留原稿，不再发起第三轮；取消、模型调用失败、输出契约或安全违规、存储异常不会触发这条静态检查重试。仅最终通过目标状态检查和全局门禁的结果创建一份新修订；未调整页面、PRD 及历史修订保持不变。此重试不重新分析需求、生成 PRD 或执行页面取证，也不自动重放历史失败任务。

在当前修订的“设计原型”中选择页面，点击“调整原型”打开弹窗。左侧查看原型并切换状态，右侧填写修改意见、连续提交调整；任务结束后弹窗保持打开，预览刷新，可继续下一轮。前端每次只提交本轮修改意见，不拼接界面中的历史消息；界面消息列表刷新后不恢复，但后端的专属 Copilot 会话及数据库审计持续保留。该操作复用可取消的 design 任务，不修改需求描述、已确认 PRD 或其他原型，分类及基线有效时无需重新分析或确认 PRD。历史修订只读，任务运行、未同步、PRD 编辑或存在待澄清问题时禁止提交。

提交时立即显示“正在提交”；以服务端返回的项目和任务作为提交回执，启动状态轮询，不依赖额外一次 GET 才确认任务已接收。弹窗展示最近设计任务的编号、状态、起止时间、最新执行步骤和静态检查重试反馈；SDK 接收、模型响应及工具进度复用已有的限频进度报告，只记录摘要，不展示推理内容。成功、失败、取消或中断均有明确终态，刷新后仍可从持久任务记录确认最近结果；对话新消息自动滚动到末尾。状态同步或操作异常直接在弹窗内提示，可“重新读取状态”，不会因此重放生成请求或覆盖原稿。

新设计采用“共享页面原型 + 声明式状态 → 渲染页面与截图”。每个 `prototypes` 条目有稳定页面 ID、标题、一份共享 HTML/CSS 和 `states`；同页正常新增、字段校验失败、新增成功共用页面骨架和弹窗结构，不再各写一份 HTML。状态仅可按 `data-prototype-node` 修改叶子文本、非秘密 input/textarea 的显示值、hidden 显隐，禁止状态独立携带 HTML、CSS、脚本或任意属性。平台强制 hidden 生效，按状态保留相应需求/验收标记。改变弹窗布局只修改共享 HTML，所有状态由同一源重新派生；状态差异不复制布局。

状态节点标记只允许绑定普通 HTML 元素，不能绑定 `html/head/style/script/template/meta/title/link/base`，也不能绑定 SVG、MathML 等非 HTML 命名空间元素。静态 SVG 图表本身仍可使用；需要状态显隐时，将标记放在其外层 HTML 容器，需要动态文字时使用 HTML 叶子文本节点。生成及一次结构纠正使用与校验器一致的元素约束，不以移除安全限制解决 `invalid prototype node element`。这类结构失败发生在浏览器静态检查之前，适用结构纠正，不是后置截图检查重试。

`screens` 仍保留为不可独立修改的派生渲染结果，以兼容预览、截图和 PRD 关联。每个派生状态含 `prototypeId`；同组状态按这个显式 ID 识别，不再按标题猜测。保存、读取、截图和导出均检查派生结果与共享源一致，篡改独立状态 HTML 会被拒绝。ZIP 额外包含 `prototype-sources.json`，保存一份页面源及状态定义。JSON/MySQL 沿用项目 JSON 结构，无需 DDL。

旧历史修订保持原样读取；尚无共享源的旧页面，首次调整时仍以“同名且关联同一 PRD 章节”确定待转换组，弹窗列出范围，模型必须将这组转换为一份共享源并保留全部状态名、标题、需求和验收映射。转换成功后仅新增修订，不回写历史；不同标题的旧页面不会被静默合并。缺失状态或退回独立 HTML 会失败。新生成任务只接受共享原型结构；已经发出的旧模型请求不会自动切换协议，必要时显式取消后重新生成，不自动重放真实任务。共享结构不等于验证了模型对全部视觉意图的理解，仍需人工评审。

HTTP 为 `POST /:id/jobs`，请求 `{version,stage:"design",screenId,instruction}`；沿用项目所有权、Origin、版本 CAS 和任务锁。服务端仅替换目标状态组并强制保留其他原型 HTML，生成新状态 ID 和修订 ID。随后在隔离 Chrome 中重新生成当前修订全部页面的截图并检查布局、可见需求和验收映射；目标原型全部状态的桌面截图和静态检查通过、全局映射契约有效后保存新修订。未修改页面的检查错误保留在完整报告中，不阻断目标调整，也不视为整份设计已通过。关联 PRD 的页面截图和导出随修订更新。失败、取消或无变化不替换原稿；历史修订保留，已有业务页面基线也保留，不重新执行整套现有页面取证。

静态预览不执行业务脚本。输入框、文本域、按钮、下拉框及 ARIA 角色可以描绘固定状态；它们的存在不是错误，确认静态设计不要求证明点击、输入或提交有效。验证报告始终保留 `interactionVerified: false`。源内容违规、目标状态布局或可见映射错误、截图证据不完整仍会阻断；新修订不继承设计确认，完整交付要求全量静态检查通过。历史修订若仅因普通控件被标红，点击“检查静态设计”即可基于已有原型生成新修订和截图证据，不调用模型、不重做 PRD，也不覆盖历史记录。

#### TMP 测试账号自动登录

TMP 已接入后端 LDAP 自动登录。私密配置位于 `data/requirement-test-login.local`，JSON 字段为 `origin`、`username`、`password`；origin 仅接受 `https://tmp.test.sunmi.com`。该文件被 `data/` 和 `*.local` 的 Git 忽略规则覆盖，不应提交、上传为需求资料或复制到前端。配置在每次 TMP 取证时读取；启动 API 时工作目录须为项目根目录。文件为本机明文秘密，应限制文件访问权限；此实现不是秘密管理服务。配置不存在时仍使用原人工登录接续流程。

配置存在时，在独立无个人凭据的 Chrome 上下文中打开 LDAP 表单、自动提交测试账号，然后使用同一内存上下文截图；任务结束关闭浏览器，不保存 storageState、Cookie 或 Token。模型只接收经过原有检查的业务截图和布局，不接收配置、认证表单或认证响应。当前配置在该 API 实例中对所有选择 TMP 的需求项目生效，并非按项目分配账号，应仅用于受信任用户的测试部署。

TMP 特例采用浏览器原生请求，不关闭 CORS 或 TLS。允许主站 GET/HEAD；静态依赖仅允许 `https://static-test.cdn.sunmi.com` 的脚本、样式、图片和字体 GET/HEAD；允许 `https://tmp-defender.test.sunmi.com` 的 GET/HEAD，自动登录阶段额外允许精确 `/tmpdefender/login` 的 POST/OPTIONS。正式截图不允许 POST。跟踪域名、任意外站、本机其他端口及业务写操作未开放；其他系统仍按下述默认同源策略执行。没有外层网络沙箱，不能把请求拦截当作完整出口隔离；后续仍需优化网络授权和低权限账号管理。

独立验证命令为 `node --import tsx server/requirements/verify-test-login.ts`，只输出认证截图成功状态、数量和图片字节数，不输出业务正文或保存截图，也不启动真实设计任务。登录截图链路通过不代表具体需求的 PRD/UI 产出或所有业务接口已验收。

取证错误区分浏览器启动、HTTP 响应、登录跳转、其他导航、空白/资源限制和加载/截图阶段，保留固定安全消息，不存储原始浏览器错误或凭据。非登录失败仍展示“取证待补充”，可修正白名单地址、提交非敏感路由/接口说明。说明作为普通来源文件保存，会使需求分析失效，需要重新分析并确认 PRD；它不是浏览器认证配置。禁止提交密码、Cookie 或令牌；前端的明显凭据赋值拦截不是完整秘密检测器。

人工登录接续：初次无登录取证发现登录阻挡后，关闭初始浏览器，在原设计任务中持久化 `job.interaction`（仅 origin、阶段和期限），任务仍为 running 并保持项目锁。工作区自动弹出“需要你完成系统登录”，可收起再打开；只有点击“打开登录窗口”才在 API 所在机器启动新的可见 Chrome 独立上下文。用户直接在该窗口登录，不复用个人配置或共享浏览器 Cookie。点击“我已完成登录，继续取证”后，关闭认证页面，恢复同源 GET/HEAD 限制，用同一上下文重新验证原业务路径后截图。仍未登录则失败，不无限循环。该接续只覆盖浏览器认证，不绕过路由与样式校验。

认证阶段仅允许目标 origin 的 GET/HEAD，以及明确列出的认证路径 POST：`/login`、`/user/login`、`/api/login`、`/api/auth/login`、`/auth/login`、`/session`（维护于 `page-capture.ts`）。其他业务 POST、跨域认证/资源、重定向链越界、弹窗、service worker、WebSocket 和下载仍被阻止。不同系统的专有认证接口须单独审查授权；当前不支持跨域 OA SSO，可尝试目标系统已支持的同源登录方式。认证页不采集截图或正文，也不向模型提供 Cookie/Token。HTTP 接口为 `POST /:id/jobs/:jobId/login`，严格请求 `{version,action:"open"|"continue"}`，沿用认证、Origin、所有权和 CAS 校验。等待上限五分钟，取消、超时、结束均关闭浏览器；内存会话不落盘。进程重启后等待任务标为 interrupted 并清除检查点，必须显式重试。远程或无图形桌面部署不能在用户电脑打开该窗口，受控远程浏览器界面尚未实现。

功能分类与浏览器导航分开：模型先在工作空间中读取业务组件、子组件导入、事件处理、状态、表单、弹窗/抽屉、Tab 内容及页面内嵌区域，比较现有行为与本次需求，再判断已有调整、独立新增或待确认。已有分类必须给出 `sourceId / path / quote` 功能源码证据；平台按来源与原始文件校验精确引用，不以路由、文件名或文字命中代替功能语义判断。证据缺失/不匹配时允许模型在同一会话中只读补查一次；仍无法核实则进入澄清，不自动改判新增。

分类确认后再追踪目标组件与宿主页面的关系、路由注册、常量及导航链接，得到截图导航地址。弹窗、Tab、抽屉及内嵌内容不需要独立路由；使用其宿主页面路径，按源码证实的 `activate` 顺序切换 Tab、打开弹窗（可 Tab → 弹窗或弹窗 → Tab），同一路径可对应多个区块和不同入口。映射结果逐区块校验，首次错误允许只读补查一次，不访问猜测地址或用默认 Tab/无关列表页替代。映射接受 JSON 或单个 JSON 围栏，引用比较可忽略快照显示行号，其他内容仍须原文匹配。完整宿主路径仍需具体导航原文证据；支持用户提供的安全查询上下文，但不自动组合通用路由 AST、推导动态参数或使用哈希路由。这是导航限制，不是功能是否已存在的分类依据；不复用开发者本机登录会话。

在“需求资料 → 现有系统地址”填写已经运行的测试系统 origin（例如 `http://localhost:5173` 或 `https://tmp.test.sunmi.com`），保存后先分析需求，再点击“生成 PRD”执行前置取证。需要代码快照和支持图片的模型，不再要求取证前已有 PRD。允许本机 localhost、127.0.0.1、::1，以及 `shared/requirement-preview.ts` 明确列出的测试 origin；当前远程白名单精确匹配 `https://tmp.test.sunmi.com`。地址不能包含路径、凭据、查询或片段，必须能从 API 所在机器访问。保存地址不启动目标系统、不开放其他网络地址，仍沿用所有权、Origin 和版本 CAS 校验。

真实截图优先。如果取证阶段无法切换目标 Tab、读取页面或找到目标内容，但所有已有区块的映射、字段或内容清单，以及样式均有可核实源码，平台会记录失败类别，继续从源码生成 PRD。确认 PRD 后可生成复刻原型并执行原型截图和静态检查。评审和导出标明“基于源码复刻 · 真实运行态未验证”，不会把原型图片当作现有页面截图。映射或样式不足、未获批准的入口、取消或保存失败仍不会放行。

在 **用户输入与证据 → 系统提取证据 → 代码壳子与页面锚点** 查看所选修订的实拍与源码复刻数量、缩略图和原图。真实截图来自 `existingPages`；若取证降级，此处显示失败码。当前修订已有匹配的降级清单但还没有现状图时，点击“生成现状复刻图”，无需重新生成或确认 PRD / 设计。打开页面不会自动调用模型。历史修订只读，没有原图或复刻图就显示无图。

复刻是对**变更前**页面的静态近似，不是目标设计或真实运行记录。作业只提供原始代码快照、页面定位和已核实的既有字段/内容；平台重新核验样式引文及组件路径，禁脚本渲染，并检查取景里的既有标签和 PNG。全部已有区块通过后，图片引用才写入 `capturePlan.sourceFallback.images`；按项目、修订、图片 ID 和哈希读取，不纳入目标设计截图或审批。失败或取消保留原修订，重试需要再次点击。没有实拍时不能据此判定还原度或业务交互。

流程为：分析与澄清 → 读取功能代码并比对需求，完成范围分类 → 仅对已有调整核实宿主路径、Tab/弹窗入口及原字段/内容并取证 → 生成覆盖全部区块的 PRD → 人工确认 PRD → 复用分类及适用的页面基线生成设计。新功能若改变原页面、弹窗、Tab、内嵌内容、表单、菜单或入口，仍属于已有调整；独立新增及原入口调整应拆分。只有需求或已确认决定支持的独立新增才无需已有路由、原字段和目标页面截图，“未找到源码或独立路由”不是新增依据；单纯有同名路由也不证明功能已存在。全部明确新增时不启动取证浏览器，零截图可生成 PRD；混合需求只取证已有部分。

范围最多 12 个区块，每个必须返回分类和具体依据。待确认分类或空范围仍返回业务范围澄清问题。分类通过后，平台立即以 `scopeCheckpoint` 保存范围骨架与分类；指纹绑定需求、来源、分析证据及业务决定，不包含取证地址版本和仅补充取证的回答。保存经过运行状态、输入指纹及版本 CAS 校验；保存失败或取消则停止，不继续取证。源码或业务输入变化会使分类失效，旧项目没有检查点时正常重新分类，不迁移真实历史记录。

映射合同返回 `pages` 与可选 `gaps`，每个未解决的已有区块应有一条有效映射或具体缺口，不能因为一个详情缺少上下文就返回全部空数组。有效映射经来源、路径、查询、激活步骤和字段/内容校验后，以 `scopeCheckpoint.mapping` 保存到原项目 JSON；不新增表或数据库迁移，也不代表已截图。后续补查与显式重试保留有效区块，仅补未解决部分；重新使用时仍按当前来源和用户批准入口验证，已失效的旧参数地址不能继续使用。

缺口区分入口上下文、源码依据、激活步骤和目标内容。入口缺口必须给出源码验证的宿主 pathname、所需查询键及引用。已有列表但缺少具体计划 ID 时，优先追踪记录名称列的链接和打开函数，提出 `discover` 视图，由平台点击已有记录取得真实参数；有批准入口的 ID 缺口也允许在一次补查中转成发现提案，不立即要求手填详情 URL。仅在无法证明安全列表入口、空列表或权限不足等情形才需要人工补充，不重问两个有效列表或猜编号。若用户已提供对应详情入口，模型不能再次报相同上下文缺口；空映射且无具体缺口在一次补查后报 `PAGE_MAPPING_INCOMPLETE`。

`discover` 每项声明用户批准的 `fromPath`、源码验证的详情 pathname、完整查询键、记录名称列、列渲染引用、导航引用，以及无 href 链接的打开函数名；可指定进入列表后的 Tab 和各详情分支的字段/内容清单。源代码只决定路径与操作方式，不决定真实记录 ID。浏览器支持原生 href、源码佐证的 SPA `<a>` 打开函数，以及 Ant Design 分离表头的表格；只在目标列的前 20 个可见行中选首个有链接的已有记录。拒绝操作列、表单内链接、禁用入口、跨环境链接、敏感参数及缺失源码关系；不填写或提交表单。非标准列表、重复同名列或没有可打开记录时明确失败，不退回列表截图冒充详情。

发现导航必须保留已批准列表的查询上下文，并匹配源码中可提取的固定查询值（如计划类型）；网络请求仍限 GET/HEAD 及原有资源白名单，WebSocket、下载和弹窗仍禁止。首次真实详情文档导航后立即锁定具体 pathname 与 query，重定向不能更换记录；SPA 打开后也核对实际 URL。每区块最多 4 个发现分支，总计仍最多 12 个截图视图、120 秒。共享详情中自测计划和测试计划等不同分支分别取证，保存各自 `viewId`、实际入口、截图及字段。新 `capturePlan.views` 校验所有分支完整覆盖，缺少一张不能生成 PRD；旧单视图修订保持兼容。全部元数据仍保存于现有项目/修订 JSON，无数据库 DDL。

取证问题携带稳定 ID、分类指纹和区块 ID，只显示相关区块的具体缺口，不再要求重新选择新增/已有。具体问题的 ID 还绑定缺口类型、路径及排序后的参数名，不受说明改写或参数顺序影响；旧泛化问题已回答后，可提出新的详情参数问题，但相同具体问题已答仍未解决则明确报 `PAGE_MAPPING_CONTEXT`，不随机换题循环。平台保留分类与有效映射，项目置为 `needs_input`，不保存不完整 PRD、不覆盖历史修订。PRD 阶段的问题通过 `clarification:prd:<jobId>` 记录来源；仅回答这些问题时记录 `prd:inputs_changed`，不使已有需求分析失效。部分回答仍等待剩余问题，全部回答后显式点击“继续生成 PRD”；不自动启动分析或重放任务。更改代码、来源或分析阶段答案仍要求重新分析；业务范围答案也会使分类检查点失效。全部已有区块具备可验证映射后才启动浏览器，仍须实际截图和字段/内容检查通过才能生成完整 PRD，保存部分提案不绕过该门禁。非法输出、缺少已有字段、截图失败等不被当作取证成功。

在“现有系统取证 → 完整业务入口”可每行填写一个同环境完整 URL 或相对路径，最多 12 条；例如 `/projects/overview/view?projectId=123`。也可在专属取证回答中粘贴同环境入口。origin 配置仍不带路径或查询。查询参数只接受有界的非敏感标识或枚举，拒绝凭据、重复参数、动态占位符和哈希。直接导航必须完整匹配用户提供的入口；经源码校验的发现提案可从这些列表点击已有记录取得详情参数，而不是由模型生成编号。路径与查询键仍需源码证据，不删除用户的查询上下文。保存业务入口仅使页面基线失效，不推翻有效分类，也不自动运行浏览器。

历史兼容：尚未回答的旧 PRD 澄清，可根据最近成功 PRD 作业时间内的“PRD 范围待确认”事件识别来源，前提是原分析仍有效；未知来源不推断为 PRD。旧版本已经提交答案并写入的 `inputs:changed` 不自动删除或解释成其他事件，因为无法可靠区分它是否同时涉及资料变更。这类项目需再分析一次，已保存答案保留，不必重建项目或重填答案；之后使用新阶段接续规则。无数据库 DDL 或真实项目自动迁移。

每个已有目标须提供源码中存在的字段或列表列名；`expectedFields` 允许不同分组或源码分支出现同名标签，按原顺序保留，不因重名整批拒绝。浏览器按唯一标签验证目标区域内的可见文字，不把重复标签当成控件数量或位置证明；仍需人工核对字段语义。确实无字段的内容提供精确标题/动作文字 `expectedContent`，不伪造字段或拿宿主其他区域凑清单。`activate` 最多 6 步，只允许源码佐证的精确 Tab 名称和弹窗入口按钮名。Tab 只点击非表单内的非提交按钮或 DIV/SPAN 语义 Tab，等待选中状态并定位其关联可见面板；弹窗只点击非表单内、非提交的原生按钮，兼容暴露 dialog 语义的抽屉。字段/内容必须在最终目标区域可见，不能被宿主同名文字冒充。旧 `openDialog` 单步形式仍兼容，不能与 `activate` 混用。仍阻断业务写请求、不填值、不提交、不猜项目 ID。加载中、主体为空、入口不明确/不安全或目标内容不可见时失败；非标准 Tab/抽屉语义仍可能需要额外适配，不是通用业务状态证明。

已有调整的 PRD 必须逐项保留取证清单中的字段名，设计必须在相关页面 HTML 中保留对应文字，遗漏则拒绝结果。新增字段依据需求和澄清决定，不要求出现在旧源码中。修订可选 `capturePlan` 保存已解决的分类及理由，用于区分“无需取证”和“取证缺失”；指纹绑定分类、最终 PRD、快照哈希、地址配置、需求描述、澄清决定和策略版本。JSON/MySQL 沿用项目 JSON，无需 DDL。设计、原型调整及静态验证修订保留分类；手动修改 PRD 后原基线不再继承，需要重新生成 PRD。设计阶段不首次补拍；旧修订未带分类时维持原门禁，不自动视为全新增。地址或代码变化使基线失效，需重新生成并确认 PRD。未配置现有系统地址的纯资料/新建需求保持原生成方式。字段清单仍依赖模型检索，标签在源码出现不等于穷尽所有字段，文字检查也不等于正确控件和业务语义验收，仍需人工审核。

指纹对 JSON 对象键递归排序后计算，避免 MySQL JSON 存储调整键顺序导致“分类基线已失效”的误报；数组顺序仍参与校验。历史指纹兼容原始序列化及 PRD、分类区块恢复的生成时键顺序；共享比较器自行处理 MySQL 分类字段重排，不依赖调用方预先规范化区块，也不丢弃额外字段。匹配时不回写旧 PRD、确认状态或取证记录，也不绕过真实内容变化检查。能够匹配的已确认历史 PRD 可直接重试设计或调整 UI，无需为此误报重新生成；不自动重放失败任务。

新生成分类使用 `classified-scope-v4` 指纹，不复用旧分类策略的取证结果，避免重试生成 PRD 时沿用错误的宿主/默认页签截图。已确认旧版本的 v3 和更早基线仍按原兼容校验供设计读取，不自动改写。Tab/弹窗步骤及目标内容随现有页面 `structure` 一并保存，并传给 PRD/设计阶段；不改变 PRD 双模板结构或数据库 DDL。

独立新增 PRD 不以样式证据为前提，但既有系统内的新增设计仍需复用可验证的主题、导航和组件风格。无目标页面截图时可使用代码风格证据；证据不足则在设计阶段提示补充样式资料，不偷偷选通用主题，也不把无关页面当成该功能的现有基线。

最多 12 个页面，每页固定 1600×1000 首屏，截图最多 5 MiB，总采集时限 120 秒；支持具体 pathname 与用户指定、源码佐证的安全查询入口，不支持动态占位符或哈希路由。导航、HTTP 重定向和最终页面都校验完整 pathname + query；同一路径更换项目/计划参数也会失败。PRD 和设计失败均保留原修订，取消不保存迟到结果；截图文件尚无孤儿垃圾回收。PRD 阶段支持原人工登录检查点，失败恢复入口为“重新取证并生成 PRD”。

浏览器使用全新、无凭据上下文，禁用 service worker、WebSocket 和下载，只允许配置 origin 的 GET/HEAD 请求，主页面导航只允许当前目标路径。跨域资源及所有 POST/PUT/PATCH/DELETE 均被拦截，脚本不由模型生成；没有 OS 网络沙箱保证，GET 本身也可能有业务副作用。只用于已授权、无敏感数据的测试环境，不用于生产或具有 GET 写接口的系统。密码输入框、email 输入及标记 data-sensitive 的元素会隐藏，但这不是完整敏感数据扫描或脱敏，截图和页面标题仍会发送给所选模型。登录页、密码表单、错误 HTTP 状态、重定向和空白页面会失败；POST 查询、跨域 API 及需登录的系统目前可能无法正常呈现，不应把失败截图作为有效业务基线。

截图按项目所有权存储并校验哈希，成功 PRD 修订记录页面、时间、指纹、字段和布局。“现有页面基线”可展开查看原截图，再与设计稿对照。“下次重新取证”使基线失效，下一次须从生成 PRD 开始，不在保存地址时操作浏览器。没有自动过期判断，系统状态变化后应主动重新取证。原截图尚未加入导出文件。

后续阶段：跨域认证授权、受控远程浏览器界面、多步菜单/详情状态、查询接口白名单、可配置敏感区域、自动视觉对照。当前仅新增上述单步非提交弹窗入口，不声称验证全部业务状态或视觉一致性。GET 也可能有副作用，应只用于已授权测试系统；认证请求授权范围不扩大。

现有系统的源码风格预检读取相邻页面、主题 Token、组件和导航样式；引用和值必须在对应来源文件真实存在，至少覆盖颜色/字体与组件/导航两类证据。未配置取证地址且证据不足时返回 `DESIGN_STYLE_EVIDENCE`；配置地址后，PRD 阶段可在风格预检失败时继续真实页面取证，设计阶段只能复用已保存的匹配基线。只有全部截图附件及可见布局结构齐全，才允许用 `captured-pages` 替代未验证的代码风格，不生成通用替代页面。现有系统不运行通用 dashboard 的整套设计系统查询，本地搜索只补充 UX 与静态布局建议。用户品牌规范、现有页面和已验证基线优先，截图不等于相似度或业务验收，仍需人工评审；历史设计不自动改写。

样式证据区分 JSON/契约错误、模型报告缺失、来源或原始文件路径不匹配、引用不匹配、值不在引用中和类别不足；事件与失败信息仅记录固定诊断原因，不保留模型原文、路径或引用内容。样式与路由引用复用相同的快照文本规范化：统一换行符、移除显示行号前缀，允许引用原始多行代码，除此之外不放宽文本和值匹配。设计阶段首次样式校验失败时，在同一模型会话中最多重新检索和核实源码一次；仍失败则只尝试已保存且完整的业务截图基线，否则停止。PRD 阶段不新增这次重试。独立新增不需要旧功能页面，但仍可使用共享主题、字体和组件作为设计依据；不会为获得样式截图而虚构既有功能路由，也不会修改已确认 PRD 或重新分析。

分析阶段最终响应为空、JSON 语法不合法或顶层字段不符合约定时，在同一会话中最多请求一次格式纠正，不重新加载资料或重跑分析工具；纠正期间工具调用被拒绝。纠正后仍需通过全部 JSON、来源证据与问题结构校验，危险对象键、超大输出和内容校验错误不触发纠正。失败提示区分 `PARSE_EMPTY`、`PARSE_JSON`、`PARSE_ENVELOPE` 等安全类别，不保留原始模型正文。PRD 与设计阶段不做自动格式纠正。

沿用现有显式 JSON/MySQL 后端选择。MySQL 不可用时不会降级 JSON。
MySQL 使用独立 `codeflow_requirement_projects` 表；上线前由管理员审核并手动执行
`sql/mysql-requirements-schema.sql`，本次开发未对真实数据库执行 DDL。
表未就绪、权限不足或租约冲突时，该模块返回 503，不阻断原编码和测试模块。
处理存储前置条件后需要由操作者安排 API 重启。不要为验证 UI 重启真实 API 或修改真实任务。

依赖 `docx` 和 `fflate` 已加入项目依赖；截图使用系统 Chrome。
设计检索在 Windows 优先使用 `py`，不应重跑 Microsoft Store 的 `python` 占位程序。
运行时不自动安装 Python、浏览器或 npm 包。

## 阅读联动

滚动阅读 PRD 时，以可视区域靠上方的功能为当前阅读内容，右侧自动展示关联设计页。目录定位也通过阅读位置触发联动；自动换稿不会滚动或聚焦 PRD。移动端隐藏的 PRD 不触发联动，重新展示后根据实际可视内容更新设计，不强制切换当前视图。
当前设计页已关联阅读内容时保留该页，避免在同一功能的多个状态稿之间反复切换；没有关联设计时保留现有页面并提示，不臆造映射。仍可手动选择设计页，直至阅读进入另一个功能。阅读状态按修订隔离。
设计稿为只读展示，不提供点击区域反向定位 PRD、选中遮罩，或文字、字号、颜色、尺寸与布局编辑。
生成尺寸遵循提供的 skill：桌面默认 1600×1000 CSS 像素；首屏按 1000px 高度设计，长内容可纵向延伸。预览在固定 1600px 宽画板中排版，由外层整体等比缩小到容器宽度，不随面板宽度重新挤压列宽或触发移动端断点，也不放大画板。已有 HTML 设计稿同样采用此展示方式，但原有 HTML 内容不会自动改写。
设计区域默认占 70%。改变窗口或左右分栏比例只改变缩放比例；预览高度随内容展开，普通评审长稿使用页面滚动；桌面 PRD 侧吸顶并保留独立滚动，审阅弹窗内双方使用各自面板滚动。当前仅生成桌面 Web 设计，不生成移动稿或要求移动端兼容；截图、静态布局和完整交付检查只使用 1600×1000 视口，不再生成移动端截图。工作区自身的窄屏浏览适配仍保留，与设计稿设备要求无关。历史修订、旧截图和旧错误不自动改写，重新检查后生成桌面检查证据；桌面布局溢出、映射缺失等仍会拦截。
已移除设计编辑入口、属性表单、画布编辑和保存操作；PRD 自身的审核编辑不受影响。
基础静态 SVG 图形经净化后可预览。历史截图也通过页面关联需求参与阅读联动，不需要组件热区。
原服务端 PATCH `/api/requirements/projects/:id/design` 兼容接口及历史修订保留，当前前端不调用该接口。

## 生成约束与技术选型

新设计采用 HTML/CSS 状态原型契约，不再要求模型生成本地业务 JavaScript。
`server/requirements/html-policy.ts` 中的生成策略同时进入设计阶段系统消息和用户请求，优先于 skills、设计建议和来源示例。
明确禁止 script、on* 事件属性、请求、存储、跳转、动态执行、外部依赖/字体/资源和活动嵌套内容，并给出允许的资源格式。
交付目标明确为静态设计稿，而非可交互原型；允许自由 HTML/CSS 视觉设计，不引入固定业务组件模板。
展开/收起、切换、提交、输入、跳转及动画均不属于设计稿能力；需要表达的业务状态以独立画板直接呈现。
模型须在单次最终输出前自查，不增加自动重试。提示词不能保证模型永远遵守约束，输出校验和隔离仍保留。
预览冻结原生控件默认操作，保留页面滚动；只运行平台自己的静态防护和尺寸测量脚本。
点击或 Enter/Space 操作设计稿均不会发送需求选择消息、定位 PRD 或添加选中遮罩；移动端不会因此切换到 PRD 视图。桌面保留左右分栏，不提供设计属性编辑或编辑历史操作。
生成约束要求为有不同描述的区域/组件分别标记真实 data-requirement-id，不只在整个页面外层标记。
历史截图通过页面关联需求参与联动，不会凭截图臆造区域映射。
旧设计仍按现有规则读取和校验，不批量改写历史内容；脚本能力检测中的正则及其误报边界本次未更改。

2026-10-31 查阅的官方技术资料与选型结论：

- [json-render](https://json-render.dev/docs)：预定义组件和动作目录，模型生成受限 JSON，平台组件负责渲染、状态与动作。适合作为需求关联、稳定节点标识、画布编辑和受控交互的后续演进候选；仍需评估组件覆盖、布局自由度、版本兼容、导出和维护成本，本次未引入依赖或迁移数据。
- [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)：在支持的模型/API 上约束 JSON Schema，减少结构错误。自由 HTML 字符串即使符合 Schema 也不保证安全或符合业务；应进一步约束组件、属性及动作枚举。当前 Copilot SDK 路径未因此自动获得该 API 能力，不改供应商或认证方式。
- [Sandpack Client](https://sandpack.codesandbox.io/docs/advanced-usage/client)：支持在 iframe 中运行静态页面、前端框架或 Node 环境，适合需要执行生成代码的另一条路线；依赖加载、网络访问、运行域和凭据隔离需另外设计，不是即插即用的无网络安全沙箱。
- [iframe sandbox](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe#sandbox) 与 [CSP](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy)：限制脚本、连接、资源和导航的浏览器边界。与生成约束、结构校验共同使用，不以提示词替代隔离，也不将浏览器隔离等同于容器级隔离。

以上为技术调研记录，不是当前实施计划。用户已选择静态设计与 PRD 关联，因此当前继续使用净化后的自由 HTML/CSS 与平台选择能力，不建设业务交互运行时或固定组件白名单。

## 失败诊断

新失败任务会在页面错误和“任务与进度记录”中保存脱敏错误码及说明：
`SKILLS`（受管资源）、`DESIGN_SEARCH`（本地设计检索）、`SOURCES`（来源读取）、
`PROMPT`（输入准备）、`SESSION`（会话初始化）、`MODEL`（模型调用）、
`MODEL_TIMEOUT`（首次响应或无进展超时）、`PARSE`（JSON 或阶段结果格式）、
`OUTPUT_VALIDATION`（具体输出校验规则）、`PROTOTYPE_VALIDATION`（原型验证）、`STORAGE`（进度或结果保存）。
输出校验只展示预定义规则，不回显模型提供的未知字段名或内容。
页面顶部仅显示最后一个任务的错误；最后任务运行中或成功时不再重复展示旧失败，历史错误仍保留在“任务与进度记录”。

HTML 安全检查使用 `parse5` 按实际标签和属性检查，CSS 使用 `css-tree` 解析。
普通文字中的 URL、SVG 的 xmlns 命名空间、内嵌 PNG/JPEG/GIF/WebP 位图及本地片段引用不再被整段正则误判。
外部资源属性、外链导航/表单、嵌套文档、HTTP 等价元数据、CSS 导入及资源能力仍被拒绝。
旧设计仍可按兼容规则读取。重新检查静态设计时，任何脚本元素或 `on*` 事件属性都属于源内容错误；即使隔离浏览器产出了视觉正常的 PNG，也不能据此确认该设计。查看 PNG 不会执行原型脚本，但截图前仍须解析不可信 HTML/CSS。设计评审还可在受限 iframe 内展示净化后的静态 HTML，并非所有预览都只加载图片。
安全拒绝包含画板序号和固定类别，例如 `css_resource`、`resource_attribute`、`script_capability`，不保存触发片段或 URL。
需求映射取自解析后的真实属性，注释、脚本/样式内容及惰性 template 不构成覆盖证据。

API 标准错误日志输出 `[requirements:job_failed]`，带 projectId、jobId、stage、phase、code 和脱敏说明。
若失败状态也无法保存，另输出 `[requirements:failure_save_failed]`；此时页面不一定能取得新诊断。
不记录 Token、来源正文、原始模型输出、原始 SDK 异常或堆栈；临时会话仍会清理。
未知 SDK 错误只能定位到模型阶段，不保证取得上游精确原因。不会自动重试或重放。
历史通用错误不会被修改，也无法恢复当时已删除的原始输出；需由操作者主动重试后采集新诊断。

## 当前限制

- 设计验证仅为脚本禁用下的静态视觉验证；`interactionVerified` 始终为 false。
- 页面净化预览可进行需求关联；活动 HTML 使用截图回退。原型业务脚本不会执行，HTML 导出是截图式原型，不是完整可交互应用。
- 浏览器请求阻断与无凭据上下文不等同于操作系统/容器级网络隔离。
- PDF、DOCX、扫描件的原始附件识别依赖实际 Copilot 模型/运行时，尚未用真实模型验证所有格式；没有独立 OCR 转换兜底。
- 来源最多 100 项、单文件 10MiB、上传每批最多 7 个、累计文件 30MiB；公开链接最多 5MiB。与原方案建议额度不同，以实现限制为准。
- PRD/画板修订存在历史，但未实现细粒度影响分析、任意修改已确认答案、项目分页及事件增量游标。
- 来源上传成功但后续 CAS 冲突时可能留下未引用文件，尚无自动清理。
- DOCX 已有结构化文本、表格和截图导出；未完成 Word 原生预览及完整企业模板排版验收。
- 自动回归使用隔离模拟环境；用户实际调用已产生持久化项目及设计记录，但这不代表所有输入格式或完整线上链路均已验收。

当前产品范围为受控静态设计闭环，不包含可交互业务原型交付；历史内容兼容及上述限制仍保留。
