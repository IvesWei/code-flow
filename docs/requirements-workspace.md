# PRD 内容组织

审阅模式的弹窗左边缘提供默认隐藏的 PRD 目录抽屉，鼠标悬停左侧空白边缘滑出，移出目录区域向左收起。目录按正文的模块、页面和功能分组，点击节点仅滚动 PRD 面板至对应内容，不挤压分栏或滚动背景。边缘目录图标支持点击与键盘打开，Escape 先关闭目录并恢复焦点，不关闭弹窗；隐藏抽屉不可进入键盘焦点。小屏目录宽度限制在视口内，支持长目录独立滚动，并遵循减少动态效果设置。普通非弹窗评审不展示抽屉。

评审区提供“宽屏评审”入口，弹窗标题为“审阅模式”，标题左对齐，设计区域宽度滑杆在同一行居中，右侧为 28px 关闭按钮。桌面左侧展示 PRD、右侧展示设计稿，滑杆表示右侧设计稿的占比，默认 70%。弹窗高度为视口减 64px、最高 900px；移动端高度为视口减 48px，保留设计/PRD 视图切换。弹窗外层不滚动，头部固定，长 PRD 和设计稿只在各自面板内滚动，避免面板与弹窗形成嵌套滚动。弹窗支持关闭按钮和 Escape，关闭后焦点返回入口；下拉菜单在弹窗内展开，背景页面在审阅期间不可操作。

PRD 评审采用嵌套列表大纲，对齐需求截图：“模块”加粗，其下逐功能展示“功能名称 / 对应场景 / 功能描述”。功能描述中的行为规则逐条列出，字段名在下一层，字段规则、选项在再下一层，选项各占一条，不以逗号拼接。没有明确场景时显示 `--`，不根据页面标题推断业务场景。完成标准保留在数据和导出中，不在阅读正文展示；页面说明及历史页面表格折叠保留，不再作为主体页面标题打断大纲。内部需求 ID、验收 ID 和设计区域映射保留，但正文不展示编号。

结构兼容可选 `blocks[].module`、`requirements[].scenario` 和 `requirements[].fields`（包含 `name`、`description`）。功能描述与字段说明使用换行分隔条目。级联选页与 PRD 使用相同模块名称。旧章节缺少模块时归入“未分组功能”，未关联章节的历史功能保留在“其他功能”；不根据旧自由文本臆造模块或字段。原有表格在前端折叠的页面说明内按行转为嵌套列表保留全部内容，导出仍保留原表格，并包含模块、场景和字段内容。修改生成规范不会自动重新生成或修改任何真实项目。

影响用户可见内容、操作能力或结果的角色权限、数据范围、删除限制、重复和部分失败处理仍属于 PRD，放在受影响功能下。接口、数据库、鉴权实现、事务、队列、部署等技术细节留给后续技术方案，不在本次自动生成技术方案。来源证据和澄清记录保留为追溯信息，不进入主体叙述。

前端和导出均按所属章节展示功能，完成标准仅保留在导出中，同一功能仅在首个关联章节完整展示。来源在界面折叠、导出放入附录。已有版本仅调整展示分组，不改写原文、不删除历史权限或技术内容；需要新的内容结构时由用户显式生成新 PRD 并重新确认，旧版本和设计记录不自动迁移。

## 基于已有项目迭代

在项目的“需求资料”区域选择本地已有项目目录，检查候选代码清单后点击“添加代码快照”。选择目录不会自动上传；仅提交去掉根目录后的相对路径和筛选代码，不提交本地绝对路径，不读取服务端任意目录。新建项目先填写本次新增或优化的目标，再补充代码来源；纯新建需求不必提供代码。

也可在“远程仓库代码”填写仓库地址、可选分支和相对模块目录，点击“拉取代码快照”。地址直接复用编码工作流校验：支持 `https://github.com/owner/repo` 与 `http(s)://code.sunmi.com/owner/repo`，可带 `.git` 或末尾斜杠；拒绝地址中的用户名、密码、端口、查询参数和片段。分支留空读取默认分支；模块目录留空按仓库范围筛选，较大仓库应指定相关目录。

远程拉取在临时目录浅克隆，不 checkout、不执行仓库代码、不读取子模块或 LFS 内容。读取 API 服务运行账户的本机 Git 全局/系统配置和已配置的凭据助手，允许使用已有仓库凭据；不弹出交互登录，不转发 Copilot 登录令牌，不继承代理环境或任意 Git 环境覆盖。凭据助手是本机可信程序，服务端需要事先配置好仓库访问权限；需要交互登录的仓库仍会失败，可继续使用已授权的本地目录上传。不会降低 TLS 校验或向链接追加 token。服务端须能访问对应主机，内网地址在外部部署环境可能不可达；HTTP 地址可能明文传输凭据，应优先 HTTPS，仅在可信网络中使用 HTTP。

快照记录规范化仓库地址、实际 commit、请求分支、模块目录和排除数量；路径保持仓库根相对形式。拉取超时为 60 秒，整个读取操作上限 90 秒，临时克隆数据按 256 MiB 巡检并在结束后复核、清理；巡检不是硬传输限额，瞬时可能超量。取消、超时或 Git 输出超限会终止进程树并等待退出，再清理临时目录；退出与清理可能使请求结束略晚于读取时限。认证、分支、证书和容量等已识别错误显示安全的修复提示，不返回原始 Git 输出；清理异常单独记录，不覆盖原始读取错误。拉取后仍受下述快照限制，超限不保存部分结果；模块目录只限制读取范围，不减少浅克隆本身的大小。每次点击都会显式获取新快照并要求重新分析，不在后台自动同步。

本地上传快照最多 200 个文件、单文件 128 KiB、累计原始 UTF-8 1 MiB。远程快照支持最多 2,000 个文件、单文件 512 KiB、累计原始 UTF-8 8 MiB，加入行号与来源说明后仍不得超过单份资料 10 MiB。容量超限拒绝整批，不按文件顺序静默截断；较大项目仍建议选择与本次需求相关的模块目录，避免无关内容占用模型上下文。这些字节限制不保证模型完整理解所有文件。

隐藏目录、依赖、构建产物、锁文件、常见敏感路径和不支持的文件类型会排除，服务端还会独立复核路径、重复项、大小、文本和明显凭据。远程读取时，未通过内容安全检查的文件不保留内容，并在快照来源说明中记录排除路径及读取局限；其余安全文件可正常导入。全部文件都未通过检查时拒绝导入。本地上传仍拒绝含不安全内容的整批资料。过滤可能保守误判，也不是完整秘密扫描；提交前仍需检查代码，模型不得臆测被排除文件的实现。

平台将代码保存为带相对路径、SHA-256 和行号的只读来源 `existing-project-code.md`，按原有来源所有权与哈希校验读取，不执行、安装或运行项目。每次分析、PRD 或设计创建独立临时工作空间，将验证后的快照放入 `sources/snapshot-N.md`，其他附件复制到空间内再提交；SDK 会话数据存放在空间之外。会话结束、失败或取消后清理整个临时目录，不修改原始资料或现有项目目录。

模型输入的 `codeSnapshots` 只包含来源 ID、登记路径、大小、行数及有长度限制的来源/排除说明，不内联整份代码。模型通过 `workspace_list`、`workspace_search`、`workspace_read` 按需检索和分段读取；通过 `workspace_write_notes` 创建或替换 `notes/*.md` 临时笔记，不能改写快照。工具只接受已登记来源与规定笔记路径，拒绝绝对路径、目录穿越、符号链接及其他文件；原生终端、任意文件读写、网络和秘密读取权限仍拒绝。这是应用层能力隔离，不是容器或操作系统级沙箱。来源正文仍是带编号代码的 Markdown，而不是可执行的检出项目；引用时使用正文中的原始文件路径/行号，不能把工具返回的快照行号当作代码行号。

初始序列化提示上限为 2,000,000 字符；单次工具结果上限 24,000 字符、累计 500,000 字符、最多 128 次调用。读取每次最多 200 行，超长行可用单行读取及 `characterOffset` 继续；搜索采用字面量匹配并返回分页和截断信息。笔记单份最多 64 KiB、最多 32 份、合计 256 KiB，并行操作串行执行以维护配额。日志只记录工具名、调用与返回量，不记录正文。模型必须报告未读、被排除和超出预算的范围，不能据此声称完整检查仓库；这些限额仍不保证所选模型的实际上下文容量或分析质量。

分析、PRD 和设计均使用保存的同一份快照，但各自创建新的临时工作空间，笔记不跨会话保留：分析要求给出现状代码锚点、与目标的差距和读取限制；PRD 区分保留、优化、新增及待确认规则；UI 优先延续代码证据中的术语、导航、组件和视觉约定，同时遵循已确认 PRD 与静态设计约束。没有代码证据时不得声称已检查现有项目。历史分析生成的“只有附件路径”等问题不会自动删除；提交其已填写答案后重新分析，新分析必须通过工具读取当前快照后重新评估缺口，不应重复索要已提供的正文。

添加快照会使原分析失效，必须重新分析后再生成、确认当前 PRD 和设计。原目录后续修改不会自动同步；需要显式添加新的快照并重新分析。现有历史修订不被改写，JSON/MySQL 沿用现有来源结构，无需新增数据库表或自动迁移。代码快照属于模型输入，会发送给所选 Copilot 模型，须确保具有提交权限。

### 原型对话调整
调整输出的需求映射错误，以及缺失/重复状态节点、重复操作和不兼容的文本/字段目标，最多允许在同一模型会话中纠正一次。纠正期间禁用工具，仍须完整通过原有契约与静态检查，不自动补造映射或删减状态。安全违规、未知字段、超限和其他错误直接失败；纠正再次失败也立即停止。共享源校验使用固定错误分类，避免将结构错误统一隐藏成 output contract violation。历史失败候选不保留，旧任务的具体违规项无法事后恢复。

在当前修订的“设计原型”中选择页面，点击“调整原型”打开弹窗。左侧查看原型并切换状态，右侧填写修改意见、连续提交调整；任务结束后弹窗保持打开，预览刷新，可继续下一轮。对话记录只在当前界面内保留，刷新页面不会恢复；每轮使用当前原型 HTML 和累积修改意见发起新的模型请求，不是恢复旧模型会话。该操作复用可取消的 design 任务，不修改需求描述、已确认 PRD 或其他原型，也无需重新分析或确认 PRD。历史修订只读，任务运行、未同步、PRD 编辑或存在待澄清问题时禁止提交。

新设计采用“共享页面原型 + 声明式状态 → 渲染页面与截图”。每个 `prototypes` 条目有稳定页面 ID、标题、一份共享 HTML/CSS 和 `states`；同页正常新增、字段校验失败、新增成功共用页面骨架和弹窗结构，不再各写一份 HTML。状态仅可按 `data-prototype-node` 修改叶子文本、非秘密 input/textarea 的显示值、hidden 显隐，禁止状态独立携带 HTML、CSS、脚本或任意属性。平台强制 hidden 生效，按状态保留相应需求/验收标记。改变弹窗布局只修改共享 HTML，所有状态由同一源重新派生；状态差异不复制布局。

`screens` 仍保留为不可独立修改的派生渲染结果，以兼容预览、截图和 PRD 关联。每个派生状态含 `prototypeId`；同组状态按这个显式 ID 识别，不再按标题猜测。保存、读取、截图和导出均检查派生结果与共享源一致，篡改独立状态 HTML 会被拒绝。ZIP 额外包含 `prototype-sources.json`，保存一份页面源及状态定义。JSON/MySQL 沿用项目 JSON 结构，无需 DDL。

旧历史修订保持原样读取；尚无共享源的旧页面，首次调整时仍以“同名且关联同一 PRD 章节”确定待转换组，弹窗列出范围，模型必须将这组转换为一份共享源并保留全部状态名、标题、需求和验收映射。转换成功后仅新增修订，不回写历史；不同标题的旧页面不会被静默合并。缺失状态或退回独立 HTML 会失败。新生成任务只接受共享原型结构；已经发出的旧模型请求不会自动切换协议，必要时显式取消后重新生成，不自动重放真实任务。共享结构不等于验证了模型对全部视觉意图的理解，仍需人工评审。

HTTP 为 `POST /:id/jobs`，请求 `{version,stage:"design",screenId,instruction}`；沿用项目所有权、Origin、版本 CAS 和任务锁。服务端仅替换目标状态组并强制保留其他原型 HTML，生成新状态 ID 和修订 ID。随后在隔离 Chrome 中重新生成当前修订全部页面的截图并检查布局、可见需求和验收映射；目标原型全部状态的桌面截图和静态检查通过、全局映射契约有效后保存新修订。未修改页面的检查错误保留在完整报告中，不阻断目标调整，也不视为整份设计已通过。关联 PRD 的页面截图和导出随修订更新。失败、取消或无变化不替换原稿；历史修订保留，已有业务页面基线也保留，不重新执行整套现有页面取证。

静态预览仍不执行业务脚本，状态通过选择器查看，不是可操作真实业务的运行环境。交互未验证警告保留在验证报告中，不阻止静态原型截图保存，也不被提升为交互已通过；目标原型布局、可见映射、截图或全局契约/浏览器失败仍阻止保存。新修订不继承设计确认，整份设计的确认和完整交付仍要求全量检查通过。修改意见用于视觉和布局调整，不用于改变业务需求；业务范围变化仍应使用原有需求修订流程。

#### TMP 测试账号自动登录

TMP 已接入后端 LDAP 自动登录。私密配置位于 `data/requirement-test-login.local`，JSON 字段为 `origin`、`username`、`password`；origin 仅接受 `https://tmp.test.sunmi.com`。该文件被 `data/` 和 `*.local` 的 Git 忽略规则覆盖，不应提交、上传为需求资料或复制到前端。配置在每次 TMP 取证时读取；启动 API 时工作目录须为项目根目录。文件为本机明文秘密，应限制文件访问权限；此实现不是秘密管理服务。配置不存在时仍使用原人工登录接续流程。

配置存在时，在独立无个人凭据的 Chrome 上下文中打开 LDAP 表单、自动提交测试账号，然后使用同一内存上下文截图；任务结束关闭浏览器，不保存 storageState、Cookie 或 Token。模型只接收经过原有检查的业务截图和布局，不接收配置、认证表单或认证响应。当前配置在该 API 实例中对所有选择 TMP 的需求项目生效，并非按项目分配账号，应仅用于受信任用户的测试部署。

TMP 特例采用浏览器原生请求，不关闭 CORS 或 TLS。允许主站 GET/HEAD；静态依赖仅允许 `https://static-test.cdn.sunmi.com` 的脚本、样式、图片和字体 GET/HEAD；允许 `https://tmp-defender.test.sunmi.com` 的 GET/HEAD，自动登录阶段额外允许精确 `/tmpdefender/login` 的 POST/OPTIONS。正式截图不允许 POST。跟踪域名、任意外站、本机其他端口及业务写操作未开放；其他系统仍按下述默认同源策略执行。没有外层网络沙箱，不能把请求拦截当作完整出口隔离；后续仍需优化网络授权和低权限账号管理。

独立验证命令为 `node --import tsx server/requirements/verify-test-login.ts`，只输出认证截图成功状态、数量和图片字节数，不输出业务正文或保存截图，也不启动真实设计任务。登录截图链路通过不代表具体需求的 PRD/UI 产出或所有业务接口已验收。

取证错误区分浏览器启动、HTTP 响应、登录跳转、其他导航、空白/资源限制和加载/截图阶段，保留固定安全消息，不存储原始浏览器错误或凭据。非登录失败仍展示“取证待补充”，可修正白名单地址、提交非敏感路由/接口说明。说明作为普通来源文件保存，会使需求分析失效，需要重新分析并确认 PRD；它不是浏览器认证配置。禁止提交密码、Cookie 或令牌；前端的明显凭据赋值拦截不是完整秘密检测器。

人工登录接续：初次无登录取证发现登录阻挡后，关闭初始浏览器，在原设计任务中持久化 `job.interaction`（仅 origin、阶段和期限），任务仍为 running 并保持项目锁。工作区自动弹出“需要你完成系统登录”，可收起再打开；只有点击“打开登录窗口”才在 API 所在机器启动新的可见 Chrome 独立上下文。用户直接在该窗口登录，不复用个人配置或共享浏览器 Cookie。点击“我已完成登录，继续取证”后，关闭认证页面，恢复同源 GET/HEAD 限制，用同一上下文重新验证原业务路径后截图。仍未登录则失败，不无限循环。该接续只覆盖浏览器认证，不绕过路由与样式校验。

认证阶段仅允许目标 origin 的 GET/HEAD，以及明确列出的认证路径 POST：`/login`、`/user/login`、`/api/login`、`/api/auth/login`、`/auth/login`、`/session`（维护于 `page-capture.ts`）。其他业务 POST、跨域认证/资源、重定向链越界、弹窗、service worker、WebSocket 和下载仍被阻止。不同系统的专有认证接口须单独审查授权；当前不支持跨域 OA SSO，可尝试目标系统已支持的同源登录方式。认证页不采集截图或正文，也不向模型提供 Cookie/Token。HTTP 接口为 `POST /:id/jobs/:jobId/login`，严格请求 `{version,action:"open"|"continue"}`，沿用认证、Origin、所有权和 CAS 校验。等待上限五分钟，取消、超时、结束均关闭浏览器；内存会话不落盘。进程重启后等待任务标为 interrupted 并清除检查点，必须显式重试。远程或无图形桌面部署不能在用户电脑打开该窗口，受控远程浏览器界面尚未实现。

路由定位采用工作空间内的迭代检索：先搜索需求业务词与页面组件，再追踪路由注册、导入常量、父子路径、部署 base 与已有菜单链接。首次映射校验失败会展示固定的具体原因，并允许在同一模型会话中继续使用只读检索工具补查一次；第二次仍失败则停止，不浏览猜测地址。多个 PRD 区块可对应同一页面。映射接受完整 JSON 或单个 JSON 代码围栏，多行源码引用比较可忽略快照显示行号，除此之外仍须原文匹配。当前尚无通用路由 AST 解析器：若完整路径只能由嵌套/常量组合产生，且没有完整导航链接等原文证据，仍明确阻断；哈希、查询与动态参数路由也未开放。这不是无限自主浏览，也不复用开发者本机的登录会话。

在“需求资料 → 现有系统地址”填写已经运行的测试系统 origin（例如 `http://localhost:5173` 或 `https://tmp.test.sunmi.com`），保存后先分析需求，再点击“生成 PRD”执行前置取证。需要代码快照和支持图片的模型，不再要求取证前已有 PRD。允许本机 localhost、127.0.0.1、::1，以及 `shared/requirement-preview.ts` 明确列出的测试 origin；当前远程白名单精确匹配 `https://tmp.test.sunmi.com`。地址不能包含路径、凭据、查询或片段，必须能从 API 所在机器访问。保存地址不启动目标系统、不开放其他网络地址，仍沿用所有权、Origin 和版本 CAS 校验。

流程为：分析与澄清 → 源码定位受影响页面和原字段清单（仅取证范围，不生成正文）→ 路由与样式核实 → Playwright/Chrome 目标状态取证 → 根据截图、源码和字段清单生成 PRD → 人工确认 PRD → 复用同一基线生成设计。每个已有页面必须提供源码中存在的字段或列表列名；弹窗另须提供源码佐证的精确入口按钮名，浏览器只点击非表单内、非提交的原生按钮，不填值、不提交、不猜项目 ID。加载中、主体为空、打不开目标弹窗或字段不可见时失败，不用列表页或导航外壳替代。没有 main 区域或非标准加载指示的系统仍可能需要额外适配；这是目标就绪检查，不是通用业务状态证明。

PRD 必须逐项保留取证清单中的字段名，设计必须在相关页面 HTML 中保留对应文字，遗漏则拒绝结果。基线与最终 PRD、快照哈希、地址配置及策略版本绑定并随 PRD 修订保存，设计阶段不再首次补拍；旧修订没有新版匹配基线时返回 PAGE_CAPTURE_BASELINE，需显式重新生成并确认 PRD，不改写历史。地址或代码变化需重新取证。未配置现有系统地址的纯资料/新建需求保持原生成方式。字段清单仍依赖模型检索，标签在源码出现不等于穷尽所有字段，文字检查也不等于正确控件和业务语义验收，仍需人工审核。

最多 12 个页面，每页固定 1600×1000 首屏，截图最多 5 MiB，总采集时限 120 秒；仍只支持不含查询/动态参数/哈希的具体路由。PRD 和设计失败均保留原修订，取消不保存迟到结果；截图文件尚无孤儿垃圾回收。PRD 阶段支持原人工登录检查点，失败恢复入口为“重新取证并生成 PRD”。

浏览器使用全新、无凭据上下文，禁用 service worker、WebSocket 和下载，只允许配置 origin 的 GET/HEAD 请求，主页面导航只允许当前目标路径。跨域资源及所有 POST/PUT/PATCH/DELETE 均被拦截，脚本不由模型生成；没有 OS 网络沙箱保证，GET 本身也可能有业务副作用。只用于已授权、无敏感数据的测试环境，不用于生产或具有 GET 写接口的系统。密码输入框、email 输入及标记 data-sensitive 的元素会隐藏，但这不是完整敏感数据扫描或脱敏，截图和页面标题仍会发送给所选模型。登录页、密码表单、错误 HTTP 状态、重定向和空白页面会失败；POST 查询、跨域 API 及需登录的系统目前可能无法正常呈现，不应把失败截图作为有效业务基线。

截图按项目所有权存储并校验哈希，成功 PRD 修订记录页面、时间、指纹、字段和布局。“现有页面基线”可展开查看原截图，再与设计稿对照。“下次重新取证”使基线失效，下一次须从生成 PRD 开始，不在保存地址时操作浏览器。没有自动过期判断，系统状态变化后应主动重新取证。原截图尚未加入导出文件。

后续阶段：跨域认证授权、受控远程浏览器界面、多步菜单/详情状态、查询接口白名单、可配置敏感区域、自动视觉对照。当前仅新增上述单步非提交弹窗入口，不声称验证全部业务状态或视觉一致性。GET 也可能有副作用，应只用于已授权测试系统；认证请求授权范围不扩大。

现有系统的源码风格预检读取相邻页面、主题 Token、组件和导航样式；引用和值必须在对应来源文件真实存在，至少覆盖颜色/字体与组件/导航两类证据。未配置取证地址且证据不足时返回 `DESIGN_STYLE_EVIDENCE`；配置地址后，PRD 阶段可在风格预检失败时继续真实页面取证，设计阶段只能复用已保存的匹配基线。只有全部截图附件及可见布局结构齐全，才允许用 `captured-pages` 替代未验证的代码风格，不生成通用替代页面。现有系统不运行通用 dashboard 的整套设计系统查询，本地搜索只补充 UX 与静态布局建议。用户品牌规范、现有页面和已验证基线优先，截图不等于相似度或业务验收，仍需人工评审；历史设计不自动改写。

分析阶段最终响应为空、JSON 语法不合法或顶层字段不符合约定时，在同一会话中最多请求一次格式纠正，不重新加载资料或重跑分析工具；纠正期间工具调用被拒绝。纠正后仍需通过全部 JSON、来源证据与问题结构校验，危险对象键、超大输出和内容校验错误不触发纠正。失败提示区分 `PARSE_EMPTY`、`PARSE_JSON`、`PARSE_ENVELOPE` 等安全类别，不保留原始模型正文。PRD 与设计阶段不做自动格式纠正。

沿用现有显式 JSON/MySQL 后端选择。MySQL 不可用时不会降级 JSON。
MySQL 使用独立 `codeflow_requirement_projects` 表；上线前由管理员审核并手动执行
`sql/mysql-requirements-schema.sql`，本次开发未对真实数据库执行 DDL。
表未就绪、权限不足或租约冲突时，该模块返回 503，不阻断原编码和测试模块。
处理存储前置条件后需要由操作者安排 API 重启。不要为验证 UI 重启真实 API 或修改真实任务。

依赖 `docx` 和 `fflate` 已加入项目依赖；截图使用系统 Chrome。
设计检索在 Windows 优先使用 `py`，不应重跑 Microsoft Store 的 `python` 占位程序。
运行时不自动安装 Python、浏览器或 npm 包。

## 阅读联动

滚动阅读 PRD 时，以可视区域靠上方的功能为当前阅读内容，右侧自动展示关联设计页。目录定位也通过阅读位置触发联动；自动换稿不会滚动或聚焦 PRD。移动端隐藏的 PRD 不触发联动，重新展示后根据实际可视内容更新设计，不强制切换当前视图。
当前设计页已关联阅读内容时保留该页，避免在同一功能的多个状态稿之间反复切换；没有关联设计时保留现有页面并提示，不臆造映射。仍可手动选择设计页，直至阅读进入另一个功能。阅读状态按修订隔离。
设计稿为只读展示，不提供点击区域反向定位 PRD、选中遮罩，或文字、字号、颜色、尺寸与布局编辑。
生成尺寸遵循提供的 skill：桌面默认 1600×1000 CSS 像素；首屏按 1000px 高度设计，长内容可纵向延伸。预览在固定 1600px 宽画板中排版，由外层整体等比缩小到容器宽度，不随面板宽度重新挤压列宽或触发移动端断点，也不放大画板。已有 HTML 设计稿同样采用此展示方式，但原有 HTML 内容不会自动改写。
设计区域默认占 70%。改变窗口或左右分栏比例只改变缩放比例；预览高度随内容展开，普通评审长稿使用页面滚动；桌面 PRD 侧吸顶并保留独立滚动，审阅弹窗内双方使用各自面板滚动。当前仅生成桌面 Web 设计，不生成移动稿或要求移动端兼容；截图、静态布局和完整交付检查只使用 1600×1000 视口，不再生成移动端截图。工作区自身的窄屏浏览适配仍保留，与设计稿设备要求无关。历史修订、旧截图和旧错误不自动改写，重新检查后生成桌面检查证据；桌面布局溢出、映射缺失等仍会拦截。
已移除设计编辑入口、属性表单、画布编辑和保存操作；PRD 自身的审核编辑不受影响。
基础静态 SVG 图形经净化后可预览。历史截图也通过页面关联需求参与阅读联动，不需要组件热区。
原服务端 PATCH `/api/requirements/projects/:id/design` 兼容接口及历史修订保留，当前前端不调用该接口。

## 生成约束与技术选型

新设计采用 HTML/CSS 状态原型契约，不再要求模型生成本地业务 JavaScript。
`server/requirements/html-policy.ts` 中的生成策略同时进入设计阶段系统消息和用户请求，优先于 skills、设计建议和来源示例。
明确禁止 script、on* 事件属性、请求、存储、跳转、动态执行、外部依赖/字体/资源和活动嵌套内容，并给出允许的资源格式。
交付目标明确为静态设计稿，而非可交互原型；允许自由 HTML/CSS 视觉设计，不引入固定业务组件模板。
展开/收起、切换、提交、输入、跳转及动画均不属于设计稿能力；需要表达的业务状态以独立画板直接呈现。
模型须在单次最终输出前自查，不增加自动重试。提示词不能保证模型永远遵守约束，输出校验和隔离仍保留。
预览冻结原生控件默认操作，保留页面滚动；只运行平台自己的静态防护和尺寸测量脚本。
点击或 Enter/Space 操作设计稿均不会发送需求选择消息、定位 PRD 或添加选中遮罩；移动端不会因此切换到 PRD 视图。桌面保留左右分栏，不提供设计属性编辑或编辑历史操作。
生成约束要求为有不同描述的区域/组件分别标记真实 data-requirement-id，不只在整个页面外层标记。
历史截图通过页面关联需求参与联动，不会凭截图臆造区域映射。
旧设计仍按现有规则读取和校验，不批量改写历史内容；脚本能力检测中的正则及其误报边界本次未更改。

2026-10-31 查阅的官方技术资料与选型结论：

- [json-render](https://json-render.dev/docs)：预定义组件和动作目录，模型生成受限 JSON，平台组件负责渲染、状态与动作。适合作为需求关联、稳定节点标识、画布编辑和受控交互的后续演进候选；仍需评估组件覆盖、布局自由度、版本兼容、导出和维护成本，本次未引入依赖或迁移数据。
- [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)：在支持的模型/API 上约束 JSON Schema，减少结构错误。自由 HTML 字符串即使符合 Schema 也不保证安全或符合业务；应进一步约束组件、属性及动作枚举。当前 Copilot SDK 路径未因此自动获得该 API 能力，不改供应商或认证方式。
- [Sandpack Client](https://sandpack.codesandbox.io/docs/advanced-usage/client)：支持在 iframe 中运行静态页面、前端框架或 Node 环境，适合需要执行生成代码的另一条路线；依赖加载、网络访问、运行域和凭据隔离需另外设计，不是即插即用的无网络安全沙箱。
- [iframe sandbox](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe#sandbox) 与 [CSP](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy)：限制脚本、连接、资源和导航的浏览器边界。与生成约束、结构校验共同使用，不以提示词替代隔离，也不将浏览器隔离等同于容器级隔离。

以上为技术调研记录，不是当前实施计划。用户已选择静态设计与 PRD 关联，因此当前继续使用净化后的自由 HTML/CSS 与平台选择能力，不建设业务交互运行时或固定组件白名单。

## 失败诊断

新失败任务会在页面错误和“任务与进度记录”中保存脱敏错误码及说明：
`SKILLS`（受管资源）、`DESIGN_SEARCH`（本地设计检索）、`SOURCES`（来源读取）、
`PROMPT`（输入准备）、`SESSION`（会话初始化）、`MODEL`（模型调用）、
`MODEL_TIMEOUT`（首次响应或无进展超时）、`PARSE`（JSON 或阶段结果格式）、
`OUTPUT_VALIDATION`（具体输出校验规则）、`PROTOTYPE_VALIDATION`（原型验证）、`STORAGE`（进度或结果保存）。
输出校验只展示预定义规则，不回显模型提供的未知字段名或内容。
页面顶部仅显示最后一个任务的错误；最后任务运行中或成功时不再重复展示旧失败，历史错误仍保留在“任务与进度记录”。

HTML 安全检查使用 `parse5` 按实际标签和属性检查，CSS 使用 `css-tree` 解析。
普通文字中的 URL、SVG 的 xmlns 命名空间、内嵌 PNG/JPEG/GIF/WebP 位图及本地片段引用不再被整段正则误判。
外部资源属性、外链导航/表单、嵌套文档、HTTP 等价元数据、CSS 导入及资源能力仍被拒绝。
脚本和事件处理器单独检查受限能力；这不是任意 JavaScript 的安全沙箱，生成脚本仍不会在预览或画布执行。
安全拒绝包含画板序号和固定类别，例如 `css_resource`、`resource_attribute`、`script_capability`，不保存触发片段或 URL。
需求映射取自解析后的真实属性，注释、脚本/样式内容及惰性 template 不构成覆盖证据。

API 标准错误日志输出 `[requirements:job_failed]`，带 projectId、jobId、stage、phase、code 和脱敏说明。
若失败状态也无法保存，另输出 `[requirements:failure_save_failed]`；此时页面不一定能取得新诊断。
不记录 Token、来源正文、原始模型输出、原始 SDK 异常或堆栈；临时会话仍会清理。
未知 SDK 错误只能定位到模型阶段，不保证取得上游精确原因。不会自动重试或重放。
历史通用错误不会被修改，也无法恢复当时已删除的原始输出；需由操作者主动重试后采集新诊断。

## 当前限制

- 设计验证仅为脚本禁用下的静态视觉验证；`interactionVerified` 始终为 false。
- 页面净化预览可进行需求关联；活动 HTML 使用截图回退。原型业务脚本不会执行，HTML 导出是截图式原型，不是完整可交互应用。
- 浏览器请求阻断与无凭据上下文不等同于操作系统/容器级网络隔离。
- PDF、DOCX、扫描件的原始附件识别依赖实际 Copilot 模型/运行时，尚未用真实模型验证所有格式；没有独立 OCR 转换兜底。
- 来源最多 100 项、单文件 10MiB、上传每批最多 7 个、累计文件 30MiB；公开链接最多 5MiB。与原方案建议额度不同，以实现限制为准。
- PRD/画板修订存在历史，但未实现细粒度影响分析、任意修改已确认答案、项目分页及事件增量游标。
- 来源上传成功但后续 CAS 冲突时可能留下未引用文件，尚无自动清理。
- DOCX 已有结构化文本、表格和截图导出；未完成 Word 原生预览及完整企业模板排版验收。
- 自动回归使用隔离模拟环境；用户实际调用已产生持久化项目及设计记录，但这不代表所有输入格式或完整线上链路均已验收。

当前产品范围为受控静态设计闭环，不包含可交互业务原型交付；历史内容兼容及上述限制仍保留。
