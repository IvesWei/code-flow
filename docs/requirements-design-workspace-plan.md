## 3. Skill 产品化方式

不把技能全文当作一次性大提示词，也不让模型自由执行 skill 中的终端安装命令。
将流程转为服务端编排，模型负责分析和内容生成，平台负责权限、状态、持久化、格式校验与交付门禁。

| Skill 行为 | 产品中的对应能力 |
| --- | --- |
| 读取附件与代码 | Copilot 原始附件输入、受控来源工具、来源证据表、可选只读参考代码 |
| VS Code 结构化提问 | 网页澄清表单、答案历史和决策账本 |
| 先规则后画面 | PRD 确认门禁，再生成正式设计 |
| 编写 Markdown | 先生成结构化 PRD JSON，再由平台导出 Markdown |
| 维护 manifest | 平台校验的页面/状态/需求/AC 映射 |
| 编写 HTML 与截图 | 隔离原型产物、受控浏览器渲染与截图 |
| Word 交付检查 | 导出作业、DOCX 结构/图片/编号校验 |

原 skill 要求至少两类输入；产品允许单份描述启动，再通过必答的目标/范围/交付类型补齐任务边界。
参考代码不是强制输入；无代码时明确显示“未做现状代码核验”，不得虚构已有能力。
将经过确认的技能和必要资源复制为当前项目的受管版本，记录来源路径、内容哈希和版本；不能运行时直接依赖桌面另一目录。
只引入实际需要的 PRD 和 UI 资源，不默认加载品牌、幻灯片等无关 prompts。
ui-ux-pro-max 为 UI 阶段硬依赖，部署时检查依赖完整性；生成请求不得自动执行 npm/pip 安装。

## 4. 用户流程与阶段门禁

1. 新建项目：标题、目标、范围、交付类型、模型、可选品牌/参考代码。
2. 添加材料：粘贴描述、上传文件、添加链接；每个来源独立显示解析结果和错误。
3. 确认解析：展示内容摘要、页数/来源定位、不可读部分与冲突，不让缺失内容被静默忽略。
4. 分轮澄清：按 P0 → P1 → 冲突收口推进，每轮通常 6-9 题；不足时不凑数。
5. PRD 草稿：分章节、需求、字段、状态、权限、验收标准展示，可编辑和提出修改意见。
6. 用户确认 PRD 基线：锁定输入和决策快照；P0/P1 未闭合不得标记定稿，P2 默认值须经显式接受。
7. 确认设计范围：页面、关键状态、目标终端、视口和视觉规范；沿用现有设计系统或明确新方向。
8. 生成 UI：产出原型、画板映射和截图，通过结构与浏览器门禁。
9. 左右联动评审：修改需求或页面、查看影响、定向重生成，保留历史版本。
10. 确认交付：冻结同一版本的 PRD、原型、截图、manifest 和导出文件。

澄清题包含：问题 ID、优先级、影响说明、关联来源/需求、2-4 个适用选项、推荐项与理由、自由输入入口。
允许保存部分答案、补充材料、暂停后返回；“跳过”不等于确认。答案冲突必须显式处理。
用户变更已确认决策时建立新修订，不覆写历史；受影响 PRD 与设计变为待更新。

## 5. 页面信息架构与左右联动

不在此轮重做全站配色，沿用当前控件体系。

桌面工作区：
```text
全局菜单 | 项目列表/折叠 | 项目标题、阶段进度、版本、保存/导出
                       | 材料 / 澄清 / 成果评审 / 历史
                       | 左：设计稿或可交互原型 | 右：结构化 PRD
                       | 页面与状态选择器       | 章节目录与规则
```

成果区默认约 55% 设计、45% PRD，支持拖动分栏、单侧聚焦和独立滚动。
平板和手机改为“设计 / PRD”切换，保留当前选中映射；不在小屏强行挤压双列。
尚未生成 UI 时左侧只显示真实阶段和阻断原因，不伪造设计预览。

结构化 PRD 内容：背景与目标、范围、角色权限、功能需求、字段与校验、状态机、异常边界、非功能需求、AC、风险与未决项。
字段/权限/状态以结构化表格呈现，长说明分段展示；保留原始来源与用户确认记录入口。

“一一对应”落地为可追踪的多对多关系，而非强行一个需求只能对应一个页面：
- 一个页面对应多个需求，一个需求也可能覆盖列表、表单、错误等多个画板。
- 通过稳定 `requirementId`、`blockId`、`screenId`、`elementId`、`acceptanceId` 建立映射。
- 点 PRD 规则：左侧切换对应页面/状态，高亮元素或映射区域。
- 点设计标注：右侧滚动并高亮对应需求/字段/AC；不强制持续同步两侧滚动。
- 原型区提供“交互模式”和“关联模式”，避免点击按钮时既执行业务演示又误触需求定位。
- 非视觉需求可标记“不适用 UI”及原因，不为后台约束伪造画板。

## 6. 输入解析范围

总体采用“Copilot 优先识别与规划，平台负责输入安全、来源留存和结果校验”，不默认自建完整文档解析/OCR 系统。
本机 SDK 的 MessageOptions 支持 file/directory/selection/blob 附件；现有 worker 已使用 file + path + displayName。
这证明附件传输通道可复用，不证明任何模型都支持所有文档格式、完整扫描件或任意网页访问。

| 输入 | 完整首版处理方式 | 限制和失败行为 |
| --- | --- | --- |
| 文字、MD、TXT | 描述及原文件直接输入 Copilot，平台保存原文 | 超长材料分批；模型必须回传实际读到的证据摘要 |
| DOCX | 优先原始附件提交，由当前 Copilot 模型/运行时读取 | 实测不支持时用受控成熟解析器抽取后重试；不执行宏，不承诺复杂排版还原 |
| PDF | 优先原始附件提交，要求按实际可识别内容返回来源证据 | 加密/损坏/未读页显式标识；不能仅凭模型声称“已读”认定完整覆盖 |
| PNG/JPG/WebP | 校验后作为原始附件或图像 blob，使用具备视觉能力的模型 | 不支持视觉时先提示更换模型，不静默丢图或仅靠文件名生成 |
| 扫描 PDF | 先验证原始附件的实际识别能力；必要时用受控工具分页转图供视觉模型读取 | 不保证所有扫描件可识别；无法读取需重新上传可读版本 |
| HTTP/HTTPS 链接 | Copilot 调用平台提供的受控来源读取工具，获取正文及快照后分析 | SDK 没有 URL 附件类型；不开放不受控网络工具，不透传登录 cookie |

文件类型、大小、路径及归属校验仍由平台完成，不能因交给 Copilot 而省略。
只有已验证原生附件无法满足的格式才增加必要适配；可选 pdfjs-dist/mammoth 等成熟工具，不把全套解析器作为前置建设。
附件能力验证必须使用有已知关键内容的无敏感样本，检查段落/表格/图片内容覆盖；依据实测结果标明支持矩阵，不能只检查 API 是否接受附件。
链接读取属于网络 I/O，必须受下文 SSRF 与来源白名单规则约束；公开页面为默认允许范围，私网/登录页面如需支持须另行明确授权与凭据隔离设计。
网页动态渲染不是仅传 URL 就自动可用；首版不绕过登录墙，无法读取时允许上传页面导出文件。
图片模型提取不是确定性 OCR，不声称字符级准确率或识别置信度；保留原图和需人工核验标记。
首版不预设外部 OCR 云服务；若要更高扫描件准确率，再单独确认供应商、费用和数据出域。
默认建议：单文件 12MiB、单项目 20 个来源、总计 100MiB、PDF 每份最多 50 页、模型处理分批且有总预算；超限不静默截断。
原始附件或必要抽取结果按容量分批处理，保留来源索引与覆盖清单；模型未提供可验证页/行定位时只记录来源级证据，不编造精确定位。

## 7. 数据与版本模型

| 对象 | 主要职责 |
| --- | --- |
| RequirementProject | owner、标题、版本、当前阶段、确认版本引用 |
| SourceDocument / EvidenceBlock | 原文件哈希、解析状态、页/行/URL、抽取器版本和证据 |
| ClarificationRound / Decision | 问题、答案、影响、确认者、来源及替代关系 |
| PrdRevision | schemaVersion、结构化章节、稳定 REQ/AC、输入与决策指纹 |
| DesignRevision / ScreenManifest | 绑定 PRD 修订、画板与状态、元素映射、产物哈希 |
| GenerationJob / Event | 阶段、attempt、租约、进度、检查点、错误与取消 |
| DeliverySnapshot | 同版 PRD/UI/截图及验证报告、导出产物索引 |

PRD JSON 是权威数据源，Markdown/DOCX 为派生产物；不反向解析 Markdown 驱动页面主数据。
需求编号一经评审不因排序/章节移动而变化；删除保留废弃记录。AC 新修订保留身份，导出显示编号可重排但映射始终依赖稳定 ID。
PRD 和 UI 分别有修订号且显式绑定；规则内容变动使相关 UI 待更新，无法可靠判断影响时保守标记整版待更新。
草稿可编辑，确认快照不可变；新材料、决策或生成参数变动均影响输入指纹。

新增独立 MySQL 表与产物目录，采用 owner + expectedVersion CAS；项目状态、作业创建和事件写入需事务一致。
不能直接复用现有 testing JSON body 容纳所有内容；文件、原型和截图存受限磁盘目录，数据库存索引、哈希和版本引用。
默认沿用部署的 MySQL；可提供显式 JSON 开发后端，不允许数据库失败后静默回退。
提供人工审核执行的增量 DDL，不修改旧任务表、不自动执行建表或迁移真实业务数据。

## 9. 任务执行、恢复与安全

项目业务阶段与作业运行状态分开。阶段含材料确认、澄清、PRD 评审、UI 评审和交付；作业含 queued/running/waiting_input/succeeded/failed/cancelled/interrupted。
持久化作业和检查点；首版同项目最多一个生成作业，全局并发设置上限，不借本功能重构旧编码任务并发。
页面离开不取消作业。服务重启将不确定运行中作业标为 interrupted；用户显式继续从校验后的检查点开新会话，不自动重放未知外部副作用。
每阶段/批次采用新 SDK 会话，传入已保存来源和决策；不复用编码会话，不依赖模型记忆维持业务状态。
阶段失败可重试当前阶段，已成功且指纹一致的产物可复用；取消后 generation token/版本条件拒绝迟到写入。

安全边界：
- 附件与网页都是不可信数据，不能覆盖系统提示、权限或触发 shell/安装软件。
- 上传做真实类型、大小、解码和解压额度检查，防目录穿越、符号链接、压缩炸弹与跨用户引用。
- 链接导入拒绝 loopback、私网、链路本地、云元数据地址及非 HTTP 协议；逐跳解析 DNS/校验重定向并绑定连接地址，限制时间/字节/类型，防 DNS rebinding。
- 受保护内网或需登录资料，首版用用户上传导出文件代替，不透传平台 token/cookie。
- 原型按受控静态 HTML/CSS/JS 产物生成，不运行模型生成的 shell、npm 脚本或任意服务。
- 用户查看生成原型使用独立隔离来源与 iframe sandbox，仅允许必要脚本，不启用 same-origin、顶层跳转、弹窗和表单提交；不加载外部网络资源，素材本地化且有白名单。
- 交互映射 postMessage 校验 source、消息 schema、会话 nonce 和有限消息类型；隔离源为 opaque 时不能仅靠 origin 判定可信。
- 浏览器验证使用独立进程/上下文、过滤环境和操作系统/容器网络约束，禁止访问平台 API、真实账号和内网。iframe sandbox 本身不能代替截图工作进程的隔离。
- 导出使用审核过的渲染器，由平台调用，模型不控制命令与输出路径；不自动调用原 skill 的安装分支。

## 10. 交付门禁与验收

- 解析覆盖可核对：每个来源有状态，失败/部分识别不能冒充已解析。
- P0/P1 闭合且确认才允许定稿；讨论稿需醒目标记，不能误导后续编码/测试。
- PRD schema、唯一 ID、引用、字段/状态/权限完整性通过校验；模型语义审查与确定性结构校验分别记录。
- manifest 中所有 REQ/AC 存在，关键需求有页面状态或明确“不适用 UI”说明。
- 每个承诺画板完成真实渲染、资源检查、截图尺寸校验和关键交互验证；未验证不能标“完整 UI 交付”。
- 截图不等于业务实现：原型交互为模拟，不连接生产业务，不声称已实现真实接口。
- DOCX 可重新打开、ZIP 有效、正文/表格/图片完整；未进行 Word 原生预览如实披露。
- 同一交付快照的 PRD、UI、截图、manifest 哈希与版本一致，不能导出新 PRD 混旧截图。
- 双向定位、历史切换、并发编辑冲突、取消后迟到结果、重启恢复均有自动化测试。
- 按现有规范使用模拟 API、隔离 Vite/Chrome，测试 1440/1367/390/320px、展开菜单、长中文、键盘与溢出；不改真实任务。
- SSRF、上传越权、恶意 HTML、跨项目消息、下载越权和模型提示注入有专项失败用例。
