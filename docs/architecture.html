03三条业务流程

箭头表示业务主路径，不意味着模型可跳过确认自动推进

需求与设计

  1. 材料与快照业务输入、代码、页面基线等来源
  2. 分析与锚点蒸馏RequirementAgent 提取证据、澄清与路由壳子锚点
  3. 保存功能分类平台 CAS 检查点；业务输入变化时失效
  4. 逐区块保存映射预检会话保存源码验证提案；仅补充具体缺口
  5. 真实页面取证关闭预检会话后浏览器同源只读采集各分支截图
  6. 撰稿、修正与复验取证及候选单独记入审计；平台按路径合并补丁、复验后生成修订
  7. 提取业务变更独立文本会话提出变更，平台核验修订与图片归属
  8. 人工确认 PRD显式指纹校验当前版本与需求范围
  9. 设计与自动校验平台检查完整画板；业务清单只关联能说明改动的目标状态
  10. 确认与导出人工确认静态设计，导出保留交互未验证标识

分析阶段沿“路由 → 绑定的 Layout 壳子 → 菜单 → 页面容器 → 目标组件与屏位”沉淀结构化 sourceAnchors，下游直接复用；stageState 核对阶段指纹。前置取证在启动浏览器或等待人工登录前关闭预检会话，取证后另开会话编写完整 PRD。开发规格保留字段、防回归规则、异常、权限、验收和完整状态映射。

PRD 字段修正与恢复：平台集中诊断选项和验收引用，允许模型一次无工具定点补丁，逐项合并到候选后完整复验；新稿的其他可纠正格式问题仍至多纠正一次。取证依据和候选写入按属主、项目、作业隔离的会话审计，不是正式修订。只有用户显式继续才由需求服务读取相邻失败或中断作业；按输入指纹、分类和证据校验，实拍须重新核验文件归属与哈希，源码降级不变成实拍。只保存依据则直接撰稿，已有候选则只修字段；旧记录只有可证明的源码降级撰稿才兼容。从头生成跳过撰稿检查点和旧截图，不清空分析或答案，不恢复旧 SDK 会话、不自动审批。见重试操作与限制。

业务评审：需求角色在独立、无工具的文本会话中依据原始需求、决定、分析证据、完整 PRD 和状态说明提出增删改及待核对项。平台用共享清单契约核对引文、修订、功能及目标状态；纯后台条目禁止挂图。PRD 与设计作业可自动整理或重选图，失败不撤销完整稿。既有双模板通过 business-review 单独补充当前修订，受所有权、版本和单作业限制；不新增修订、不改变静态校验与审批。业务网页和业务 Word读取同一清单；未整理不显示全量替代稿，引文核对不等于验证业务语义。

设计生成区分 incremental（绑定真实 sourceAnchor 锁定存量壳子与非改动区）与 redesign，状态支持声明 proves 及精准入镜模式（viewport + scrollTo、element 特写、fullPage 长图）。整份设计生成与单原型微调均由平台在隔离无脚本 Chrome 中自动生成截图、校验静态布局并在首次视觉检查失败时自动携带具体诊断重试一次；单原型微调兼容同一区块的多分支 discover 原始页面基线与源码复刻基线。

原型截图使用 static-script-disabled 模式、1600×1000 桌面视口及无凭据浏览器上下文，并拦截外部请求；这不是操作系统级网络隔离。静态输入框和按钮可表达固定状态，不因未点击或未提交而阻断确认。脚本、事件属性或违规资源仍是源内容错误；即使像素检查通过也不能确认。全量静态证据通过后，interactionVerified 仍为 false。

缺口问题的稳定标识绑定区块、缺口类型、路径与参数名，不绑定说明措辞。旧泛化问题已答后可补问新的具体详情缺口；相同具体缺口已答仍未解决则明确报错。空映射且无具体缺口在一次补查后属于模型结果不足，不能推断为用户遗漏全部入口。真实取证优先；映射完整且样式有可核实源码时，指定浏览器取证失败可转为源码复刻，修订记录失败类别与区块字段，不写入 existingPages。设计复用源码基线生成静态原型，评审与导出明确标注未验证真实运行态。

可选的现状图作业：用户在系统证据区发起 reconstruct → 平台校验当前修订、版本与取证指纹 → DesignAgent 在独立会话根据原始快照、定位信息和既有清单生成变更前 HTML，不接收目标稿、业务变更或设计截图 → 平台静态渲染核对取景内字段和 PNG 后，整组登记到 sourceFallback.images。图片由所有者按修订读取并核验哈希；不会补拍、重跑 PRD、覆盖目标稿或改变审批状态。

具体列表或详情入口由用户提供。只有列表时，Agent 可按源码提出 discover 视图：记录名称列、链接渲染、打开函数、详情 pathname、查询键及字段；平台验证提案后，从该列最多前 20 个可见行中选择首个有链接的已有记录，点击真实链接取得参数。不允许操作列、表单内链接、猜 ID 或新建样例。兼容普通 href、源码佐证的 SPA 链接及 Ant Design 分离表头；自定义列表不在支持范围时明确失败。

发现过程仍限制主文档同源和 GET/HEAD，继承列表查询上下文，核对源码中的固定参数；首次真实详情导航后锁定具体 URL，重定向不得换计划。每区块最多 4 个分支、全任务最多 12 个取证视图、采集总时限仍为 120 秒。同一区块的不同分支分别保存 viewId、实际路径和截图，capturePlan.views 校验完整覆盖，不将某一类计划截图当作全部分支。空列表、无权限或不安全入口明确失败，不提交写请求。字段文字检查仍不等同于控件位置或业务语义验收。见 分类与基线指纹、逐区块映射、来源校验与记录打开、入口合同及 实际浏览器执行。

编码工作台 / 既有 CodingWorker 路径

  1. 任务与附件编码目标、PRD、设计图
  2. 工作区与编码Git 克隆 / 任务分支；CodingAgent
  3. 工程检查平台运行仓库已有 test / build
  4. 人工发布确认PUBLISH_PENDING；确认推送或明确跳过
  5. 生成 / 评审自测确认后启动；规划、脚本编写、独立评审
  6. 执行与结果平台运行测试；REVIEW / SUCCESS

恢复和补跑继续沿用原任务与阶段产物。生成、评审、浏览器规划使用分阶段会话并共享父预算；编码完成不等于已获推送批准，自测成功也不把未选用例算作通过。

独立用例规划 / 执行

  1. 导入来源材料、代码与来源指纹
  2. 规划与独立评审TestPlanningAgent + test-review
  3. 发布用例包平台门禁；不可变包与版本
  4. 创建执行工作区绑定用例包与代码版本
  5. 实现与准备确认模型提案 → 平台校验写入；安装及绑定审批
  6. 实际执行平台 runner / Playwright；结构化结果与证据

用例生成状态、设计评审结论、执行准备状态、真实运行结果分开保存和展示。环境失败不改写为设计失败，设计通过不代替实际运行通过。

04受控 Agent 边界

角色不是独立进程；平台可配置子角色，模型不能自行委派

平台入口角色 需求 / 设计 / 编码 / 独立测试规划 / 独立测试实现

CodingWorker 按自测阶段配置

coding → test-planning / test-authoring / test-review / browser-planning

箭头表示平台代码选择角色；子角色与父角色共用根预算。不是模型之间发送任务。

测试规划中的独立评审

test-planning → test-review

评审创建全新阶段会话；原始依据与待评审定义是输入，脚本本身不能替代独立验收依据。

统一边界来源：agents/profiles.ts、agents/runtime.ts、agents/workspace.ts。以下数字是每次根执行及对应角色的 SDK send / 工具尝试上限，不是 token 或金额硬上限。

交接与旧版本防护

输入复制并冻结，交接记录版本和指纹；模型返回后及最终保存时核验来源，取消或过期结果不覆盖新版本。

权限与执行防护

角色限制与原权限取交集；直接文件访问限制工作区和精确只读附件。审批、安装、测试和发布仍由平台控制。

预算、互斥与可观察性

同资源执行互斥，子角色不能重置父预算；记录真实角色、父角色、运行 ID 和请求指纹。编码先保存完成审计，再标记成功。

当前限制：没有 OS 级沙箱、分布式队列或持久化图执行器；编码仍保留已有受控 shell。重启按原规则标记中断并显式继续 / 重试，不保证任意节点自动恢复或副作用 exactly-once。Agent completed 只表示调用结束，不代表 PRD 已确认、测试已通过或发布已获批准。
