# 后台启动日志排查

在项目根目录的后台终端执行 `npm run dev:api` 后，查看 `[startup]` 日志，而不是只看 Vite 地址。前端在另一个终端执行 `npm run dev:web`。`npm run dev` 仅启动前端，两种服务独立停止，不要重复启动后台或前端实例。

## 阶段顺序

1. API 入口开始：打印 PID 和 Node 版本，静态模块已完成导入。
2. 环境配置加载：加载进程环境或约定的环境文件。
3. 存储配置校验：确认 JSON/MySQL 配置有效。
4. MySQL 连接、单实例锁与 schema 检查；JSON 模式跳过这一步。
5. 任务加载与重启状态保存：读取持久化任务并保存中断状态恢复结果。
6. 存储初始化完成：打印实际模式 mysql 或 json。
7. API 端口监听：完成后才输出 `API listening on ...`。

每个阶段记录开始、完成或失败以及耗时。异步阶段等待超过 30 秒，会提示尚未完成；这是诊断警告，不会自动取消、重连或重试操作。同步阻塞时事件循环无法及时执行警告。实际数据库连接与查询仍使用已有超时设置。

## 如何判断

- 完全没有“API 入口开始”：检查 watcher 是否启动子进程、模块导入或编译错误。入口日志不覆盖静态导入前的故障。
- 某阶段只有“开始”：优先排查该阶段；超过 30 秒仍未完成会有警告。
- “失败，错误代码”：根据阶段和代码排查，不把所有监听错误都当作端口占用。
- `EADDRINUSE`：已有实例占用端口，停止原启动终端；不要只杀可能被 watcher 重新拉起的子进程。
- `ECONNREFUSED`、`ETIMEDOUT` 等发生在 MySQL 初始化阶段：检查数据库服务、网络及连接配置。
- `UNKNOWN`：底层未提供可安全输出的代码，不能据此确定根因；结合失败阶段进一步核查。
- Vite 的 `ECONNREFUSED 127.0.0.1:3001`：代理连接不到后台，是结果而不是后台失败原因。
- 收到 SIGINT/SIGTERM 后出现 `[shutdown]`：后台正在关闭，并输出存储关闭与待写入任务保存的进度。

Express 5 监听回调可能携带错误。平台仅在无错误时输出启动成功；端口冲突测试验证不会同时误报成功。

## 日志安全

诊断日志只输出固定阶段名、PID、Node 版本、存储模式、耗时、监听端口和安全错误代码，不输出数据库地址、密码、OAuth Secret、token、任务正文、原始异常堆栈或连接详情。

日志用于定位问题，不保证启动自动恢复或任务自动续跑。修改源码可能触发开发 watcher 重启，重启后仍需重新登录；应尽量在没有任务执行时进行。

## 前端监听边界

任务产生的文件不属于平台前端源码。Vite 忽略默认 `data`、前端配置中的自定义 `DATA_DIR`、`server`、`docs` 和 `dist-server`；任务 HTML、任务 TypeScript 配置和 SDK 会话文件变化不会导致平台刷新。平台前端与共享源码仍可热更新。

自定义数据目录应在前后端使用相同配置；若只给后台终端设置 DATA_DIR，前端不会获知该目录。前端从自己的进程变量或项目 `.env` 读取 DATA_DIR，修改后应重启前端。此配置只隔离文件监听，不构成文件访问权限控制或文件系统沙箱。
