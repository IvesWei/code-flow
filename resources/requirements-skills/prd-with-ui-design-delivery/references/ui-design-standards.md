# UI 设计与交互规范

## ui-ux-pro-max 前置要求

本规范负责把设计建议收敛为适合当前产品的可实现规则，不替代 `ui-ux-pro-max`。进入 UI 生成阶段前使用 `scripts/ensure_uiux.py --check` 确认依赖；优先识别官方 Copilot Skill，同时兼容旧 Prompt 布局：

```text
.github/skills/ui-ux-pro-max/SKILL.md
.github/skills/ui-ux-pro-max/scripts/search.py
.github/skills/ui-ux-pro-max/data/

# 或兼容布局
.github/prompts/ui-ux-pro-max.prompt.md
.github/prompts/ui-ux-pro-max/scripts/search.py
.github/prompts/ui-ux-pro-max/data/
```

若缺失，先运行 `--dry-run` 本地预览来源与安装命令，再运行 `--install`。安装器使用官方仓库 `https://github.com/nextlevelbuilder/ui-ux-pro-max-skill` 推荐的 `npx ui-ux-pro-max-cli init --ai copilot` 项目级安装方式；安装后必须重新校验。发现部分安装时不得自动覆盖，应报告残缺路径并获得用户确认后再处理。读取检查结果返回的实际指令文件和搜索脚本，不硬编码某一种目录布局。

新产品或无成熟设计系统时运行 `--design-system`；已有产品时至少运行一个相关 `--domain` 查询和一个目标 `--stack` 查询。搜索结果是设计建议，不能覆盖用户要求、现有品牌规范、仓库技术约束和 PRD 业务规则。

## 设计输入与双轨保真策略

优先级从高到低：

1. 用户提供的设计系统和品牌规范。
2. 当前路由真实绑定的 Layout 壳子、菜单树以及目标页面已有的组件、字体、间距和交互。
3. 仓库已有且经校验一致的高保真原型（注意：若历史原型壳子与真实路由 Layout 冲突，一律以真实源码为准，禁止抄错历史原型）。
4. 经核验的 `ui-ux-pro-max` 检索结果。
5. 本规范的通用默认值。

不得因追求视觉新颖而破坏现有后台系统的一致性。在编写原型前必须先判定模式：

- **存量页面局部微改（`mode: "incremental"`）**：
  1. 先从路由配置（如 `src/config/routes.tsx`）查明该路径挂载的具体 Layout（例如是仅左侧 `192px` 浅色侧栏的 `ConfigLayout`，还是带顶部 `GlobalHeader` 的 `BaseLayout`，或是无侧栏路由组）及菜单高亮项。
  2. 原封不动复刻该 Layout 外壳、非改动区的筛选器、Tab 栏、表格列顺序与操作按钮位置，严禁凭空添加真实页面不存在的黑色顶栏、环境状态点或虚假菜单。
  3. `ui-ux-pro-max` 仅用于指导本次新增/变更的那块局部组件（如新增弹窗、新统计卡片、新阻断反馈），不得重排其余 90% 的存量界面。
- **全新页面或整页重设计（`mode: "redesign"`）**：
  1. 外层导航壳子与主题变量（品牌主色、字族、圆角、基础字号）仍须严格对齐目标路由所属的真实 Layout。
  2. 页面内容区结构、图表密度与交互层次结合 `ui-ux-pro-max` 检索结论与本规范设计。

## 页面结构

- 运营和管理后台优先使用稳定导航、紧凑信息密度和可扫描表格。
- 固定格式区域使用明确尺寸或网格约束，避免内容变化导致布局跳动。
- 页面区块使用无框分区或全宽内容带；卡片只用于独立、重复或需要边界的对象。
- 禁止卡片嵌套卡片，避免装饰性大圆角和无业务意义的渐变球体。
- 页面标题、筛选、主要操作、数据主体和分页形成稳定视觉顺序。

## 控件选择

- 二元配置使用开关或复选框。
- 有限互斥选项使用单选、分段控件或选择器。
- 数值使用输入框、步进器或滑块，并展示单位和范围。
- 工具操作优先使用熟悉图标并提供 tooltip。
- 危险操作使用明确文案、影响摘要和二次确认。
- 异步任务展示运行阶段、百分比或计数、失败原因和重试。

## 字段与状态

- 表单字段顺序遵循业务决策顺序，不照搬数据库字段顺序。
- 条件字段在触发条件旁展示，隐藏时说明是否清空原值。
- 状态标签颜色保持一致：成功、警告、错误、处理中、停用不得混用。
- 阻断问题必须出现在主操作附近，不能只藏在详情或 toast 中。
- 空状态说明下一步可执行动作；无权限状态不得泄露受限数据。

## 文案

- 使用业务术语和真实字段，不使用 Lorem Ipsum。
- 按钮使用动作动词，如“确认并生成”“升级引用”“保存草稿”。
- 风险提示说明影响对象、阻断原因和解决方式。
- 不在页面大段解释产品功能；说明性内容放在帮助、tooltip 或 PRD。

## 原型路由

推荐使用单 HTML 多状态：

```text
index.html?screen=list
index.html?screen=create
index.html?screen=impact
index.html?screen=list&clean=1
```

`clean=1` 必须隐藏画板切换器和调试控件，供截图及 Figma 导入。

## 精准截图定位与固定视口检查

默认基准视口 `1600×1000`。不得无脑对所有页面只截首屏 `(0, 0)`，必须按目标改动位置选择 `captureMode`：

- **首屏整页上下文（默认 `captureMode: "viewport"`）**：适用于改动点在首屏上半部或全屏弹窗/遮罩态，画面宽高严格等于 `1600×1000`。
- **中下屏区块带上下文（`captureMode: "viewport"` + `scrollTo: "#target-section"`）**：当改动点位于页面下半截（如底部趋势图、审批流时间线、页脚操作栏）时，必须配置 `scrollTo` 将目标区块滚动至视口焦点位置，避免首屏截图把改动点裁切在 `1000px` 之外。
- **独立模块/弹窗特写（`captureMode: "element"` + `selector: "#modal-card"`）**：适用于需要单独放大展示某个复杂卡片、局部表格或确认框细节（可设 `padding` 保留适度呼吸边距）。
- **纵向长页面全览（`captureMode: "fullPage"`）**：适用于多段统计报表或长表单需要一张图展示完整上下游关系的场景，宽度固定 `1600`，高度自适应完整内容。
- **动态悬浮/展开态（配置 `actions` + `waitForSelector`）**：需要展示口径说明 Tooltip、ECharts 悬浮框、下拉菜单或抽屉展开态时，在 manifest 中声明 `hover` / `click` 动作与 `waitForSelector`，等待本地字体与图表渲染稳定后再截图。

每张画面检查：

- 目标改动区域处于画面视觉中心或完整入镜，无首屏截断。
- 文档宽度不超过视口，无意外横向滚动。
- 表格最后一列、分页和批量操作完整。
- 抽屉、弹窗四边及底部操作完整。
- 长中文不覆盖相邻内容。
- Logo、图片、本地字体、图表脚本等资源全部 HTTP 200 成功加载且渲染完成。
- 固定页脚或原型导航不遮挡业务控件。

若交付还要求移动端，为核心流程补充 390×844 画板，不能仅缩放桌面布局。

## Figma 交付

先检查当前 Figma 工具是否具备画布写入能力。若只有 Dev Mode、检查或导出能力：

1. 启动可访问的本地 HTTP 服务。
2. 使用干净导出 URL。
3. 在 Figma 使用可信 HTML-to-design 插件导入。
4. 逐屏导入为命名清晰的 Frame。
5. 抽查字体、图标、表格和自动布局。

不得把 PNG 导入说成可编辑设计稿，也不得声称未执行的 Figma 导入已经完成。
