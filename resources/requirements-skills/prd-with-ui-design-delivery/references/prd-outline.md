# PRD 结构与追踪规范

## 推荐章节

1. 文档修订记录
2. 需求依据
3. 业务背景与目标
4. 当前业务与系统现状
5. 范围与非范围
6. 术语、对象与角色
7. 权限矩阵
8. 功能需求详情
9. 数据关系、字段、版本与状态机
10. 导入、导出和批处理
11. 通知、待办和审计
12. 异常与边界场景
13. 非功能需求
14. 埋点与成功指标
15. 验收标准
16. UI 页面与状态设计
17. 发布、迁移、灰度和回退
18. 风险、依赖和评审关注项

章节可按产品特性合并，但不得遗漏适用的规则域。

## 需求编号

复杂项目为主要业务规则增加稳定编号：

- `REQ-AUTH-01`：权限。
- `REQ-DATA-01`：数据与唯一性。
- `REQ-FLOW-01`：主流程。
- `REQ-AI-01`：AI 能力。
- `NFR-PERF-01`：非功能要求。

编号一旦进入评审，不因章节移动而改变。删除需求时保留编号并标记废弃，避免后续引用漂移。

## 验收标准

使用连续 `AC-01` 编号，格式为“场景 + 可观察结果”。每条至少包含一个可通过 UI、接口、数据或审计验证的结果，不使用“正常”“合理”“友好”等不可测表述。

覆盖以下类型：

- 主流程成功。
- 权限允许与越权拒绝。
- 空值、重复、并发和幂等。
- 状态冲突、撤回、删除和被引用影响。
- 异步任务失败、重试和恢复。
- 快照、版本和历史一致性。
- 迁移和回退。

## UI 追踪矩阵

PRD 必须包含以下表格：

| 画板 ID | 页面/状态 | 关联需求 | 关联 AC | 关键交互 | 权限/异常 |
|---|---|---|---|---|---|
| example-list | 列表默认态 | REQ-FLOW-01 | AC-01 | 搜索、新建、分页 | 无权限隐藏新建 |

manifest 中的 `requirements` 和 `acceptanceCriteria` 必须能回查到该矩阵。

## 字段表

字段定义至少写明：名称、类型/选项、是否必填、来源、默认值、编辑角色、校验、展示规则和是否进入版本/快照。动态字段还需说明触发条件和清空规则。

## 状态机

状态机至少写明：当前状态、执行角色、动作、前置校验、目标状态、通知、审计和失败行为。状态与按钮必须在 UI 原型中保持一致。

## 证据标记

写作过程中内部区分：

- `[需求]`：用户或正式材料明确提出。
- `[代码]`：当前系统可验证行为。
- `[确认]`：用户在本轮明确决策。
- `[推导]`：基于一致性的产品建议。

正式 PRD 可去掉标记，但决策账本中必须保留来源。
