# UI 设计图交付质量门禁

## Gate 1：输入边界与源码页面基线

- 影响页面主流程、字段显隐、按钮权限与阻断分支的 P0 规则已确认（独立模式下已澄清，联用模式下已对齐上游决策账本）。
- 存量页面改动已沿“路由配置 → 绑定的 Layout 组件 → 菜单配置 → 页面承载容器（全页或列表页弹窗/抽屉）→ 目标子组件与样式”完成取证回溯。
- 本地服务或测试环境可用时已核对运行态基线；纯静态复刻时已定位仓库真实静态资产（Logo、本地字体、组件色值）。

失败时：不得凭印象脑补页面外壳或直接进入高保真编码。

## Gate 2：设计检索与存量保真

- `ensure_uiux.py --check` 通过；`ui-ux-pro-max` 指令文件、搜索脚本和数据集完整，且已按场景执行对应检索。
- 设计依据记录了查询意图、采用的建议以及因现有品牌/技术栈而舍弃的建议。
- `mode: "incremental"`（存量页面改动）已在 `ui-manifest.json` 声明真实存在的 `sourceAnchor`（`route`、`layout`、`pageFile`），原型导航壳子、菜单高亮及非改动区结构与真实代码一致，未误改非本期存量区域。
- 主要按钮的可见性、可用性、文案动词及表单字段与业务规则（及联用时的 PRD 定义）一致。
- 关键业务状态（正常、新建/编辑、确认/阻断、加载/进度、空数据、错误恢复、只读/无权限中的适用项）已成组覆盖。

失败时：修正原型或画板清单，不允许图规不一。

## Gate 3：浏览器渲染与精准截图

- 所有 manifest URL 返回成功，且子资源（字体、脚本、SVG/图片）无 HTTP 4xx/5xx 或未捕获 JS 异常。
- 截图前已完成字体就绪（`document.fonts.ready`）、图表/异步节点等待（`waitForSelector`）及必要的预交互（`actions`）。
- 每张 PNG 尺寸符合对应 `captureMode` 规则（`viewport` 精确匹配视口宽高；`fullPage` 匹配视口宽且高度完整；`element` 非空有效且无边缘杂色漏底）。
- 中下屏改动或弹窗已合理控制布局或配置 `scrollTo` / `element` 准确入镜，**已逐类打开 PNG 人工像素检视**，无目标区被首屏裁切、遮挡、意外横向溢出或空白画布。
- 截图为 `clean=1` 干净导出态，不包含画板切换器或调试控件。

失败时：修复原型或 manifest 参数后重拍受影响画板，严禁保留残次截图。

## Gate 4：UI 契约与资产洁净度

- `validate_ui.py` 校验通过（与 `prd-from-requirements-and-code` 联用时须附加 `--require-prd-links` 通过）。
- 每个画板均包含清晰的 `proves` 状态证明说明；联用模式下 `requirements` 与 `acceptanceCriteria` 已准确绑定开发规格版编号。
- 截图文件名稳定语义化，不使用 `final2`、`tmp`、`new-new` 等临时命名，`screenshots/` 目录下无未注册的孤儿图片。
- 最终回复（或向文档 Skill 的交接说明）只声称实际执行并通过的检查。
