# 交付质量门禁

## Gate 1：需求完整性

- 业务目标与成功指标有对应关系。
- 本期范围和非本期范围不冲突。
- P0 决策已确认或显式标记待确认。
- 角色、数据范围、前后端鉴权均有定义。
- 对象、主键、唯一键、版本和快照语义明确。
- 主流程、失败路径、通知、审计和迁移闭合。

失败时：不得进入定稿和最终 UI 像素设计。

## Gate 2：PRD 可验收性

- AC 编号连续且无重复。
- 每个 P0/P1 规则至少有一条 AC。
- AC 包含可观察结果，不使用模糊形容词。
- 字段表、权限矩阵、状态机和异常表互不矛盾。
- 埋点可支持成功指标计算。

失败时：先修 PRD，再更新原型。

## Gate 3：UI 追踪性

- `ensure_uiux.py --check` 通过；`ui-ux-pro-max` 指令文件、搜索脚本和数据集完整，且已执行符合场景的设计检索。
- 设计依据记录了查询意图、采用的规则和因现有设计系统而舍弃的建议。
- 每个关键画板关联需求和 AC。
- 主要按钮的可见性、可用性和结果与权限规则一致。
- 页面字段与 PRD 字段表一致。
- 状态、错误、阻断和完成结果在画板中有代表性覆盖。
- 危险操作展示影响范围及二次确认。

失败时：修正画板或 PRD，不允许两边使用不同术语规避冲突。

## Gate 4：浏览器与截图

- 所有 manifest URL 返回成功。
- 页面资源无 404。
- 每张 PNG 尺寸与 manifest/命令一致。
- 人工检查代表性画板，无裁切、遮挡、溢出和空白画布。
- 截图为干净导出态，不包含调试和画板导航控件。

失败时：修复后重拍受影响画板；不要继续嵌入旧图。

## Gate 5：DOCX

- `python-docx` 可重新打开。
- `py -m zipfile -t` 通过。
- 核心章节、关键词和 AC 可在正文与表格中检索。
- manifest 中每张图都已嵌入 `word/media/`。
- 图片按版心缩放，无本机绝对路径或失效外链。
- 段落、表格、图片和文件大小非异常。

环境允许时转 PDF 检查目录、分页、表格宽度、图注、孤行和中文字体。无转换工具时在交付说明中披露。

## Gate 6：最终一致性

- Markdown、DOCX、HTML 和截图使用同一版本号与日期。
- PRD 的 UI 清单与 manifest 数量一致。
- 截图文件名稳定，不使用 `final2`、`new-new` 等临时命名。
- 清理探针图、临时 DOCX、测试输出和一次性脚本。
- 最终回复只声称实际执行并通过的检查。
