# PRD固定双模板质量检查清单

检查两份文档；任何适用项不通过均需修正或明确阻塞。检查清单属于工作过程，不附加到PRD正文。

## Gate 1：输入、证据与确认

- [ ] 已读取需求材料、原型/图片说明、批注、删除线及相关上下文。
- [ ] 已明确本期模块、功能与范围外内容；旧版PRD只继承适用业务内容，不沿用旧章节结构。
- [ ] 已定向定位菜单/路由、页面、表单、API、类型、权限、状态流转及适用的集成模块。
- [ ] 涉及存量页面改造时，已沿“路由配置 → 绑定 Layout 壳子 → 菜单层级 → 页面父容器 → 目标子组件/弹窗”完整回溯页面坐标，未仅凭局部子组件猜测页面外壳或区块位置；环境可用时已核对真实运行态页面基线。
- [ ] 已在内部区分需求原文、代码现状、用户确认与推导；取证表和差距矩阵未进入PRD。
- [ ] 数据粒度、唯一键、字段责任、状态、权限、引用/快照、导入失败及历史处理等适用决策有依据。
- [ ] 冲突采用最新明确确认结果；P0未决时未声称定稿。
- [ ] 所有未决事项已在所属功能原位标注“待确认”，无编造规则、空白占位符、问卷或默认放行权限。

## Gate 2：固定结构与格式

- [ ] 两份交付物明确标识业务评审版与开发规格版，输出格式符合用户要求。
- [ ] 每份文档只有一个标题，后面直接进入首个模块大纲。
- [ ] 无封面、目录、修订记录、文档版本行、阅读指引、方案概述、过渡文字或独立章节。
- [ ] 无一页速览、确认栏、签字表、集中拍板问题或解释设计理由的文字。
- [ ] 无功能/字段/状态/权限/验收表格，所有内容逐级挂在连续大纲上。
- [ ] 列表层级为`●（0）→ ○（1）→ ■（2/3/4）`，每层缩进一致，无跳级或扁平化。
- [ ] 模块整行加粗；功能行仅名称加粗，对应场景与功能描述不加粗。
- [ ] 各小节引导行加粗，行为、字段、枚举、规则、异常、权限和AC子条目均不加粗。
- [ ] 多个功能按规定小节顺序组织，多个模块分别成树，无空引导行，不插入其他结构。

## Gate 3：功能自包含与业务闭环

- [ ] 开发版每功能按固定顺序包含场景、描述、逐条系统行为、字段、状态流转（仅流程类）、设计稿、规则、异常、权限和验收标准；业务版不设异常、权限和验收标准小节，并按需省略无界面增删改的“该功能涉及的字段”及无后端隐性复杂逻辑的“业务规则与生成逻辑”。
- [ ] 只有涉及流程的功能包含状态流转；其他功能已删除整个状态流转小节。
- [ ] 业务版无界面字段增删改或无后端复杂业务规则时已整节省略对应引导行（未留空或写凑数说明）；开发版无适用字段或规则时有明确陈述，两版均无空引导行。
- [ ] 业务版字段仅标出原有用户操作界面上新增、删除、变更的字段（不含未改动旧字段与纯后端隐藏字段）；开发版字段包含界面变更及对接所需字段，均不改写成宽表。
- [ ] 流转包含源状态、目标状态、触发事件、前置条件、触发角色及通知/锁定/日志等副作用。
- [ ] 通知、导入、批处理、引用/删除、实时/快照、审计、迁移/兼容均在所属功能下说明适用规则。
- [ ] 正常、加载、空数据、请求失败、业务异常、无权限、重复操作等适用状态有明确处理。
- [ ] 适用的重复/并发唯一、部分失败、幂等重试、流程中断、依赖缺失、引用删除和历史数据影响已覆盖。
- [ ] 适用的分页、大数据量、长文本、特殊字符及性能上限有已确认规则或明确“待确认”标注。

## Gate 4：双版差异与一致性

- [ ] 两版模块、功能、场景、描述、行为、状态与设计稿的业务口径一致；业务版保留的界面变更字段、后端复杂规则与开发版对应定义无冲突。
- [ ] 业务评审版为简洁、明确的产品业务陈述，无工程排查过程及MOD/FR/FLD/TR/BR/EX/RM/AC编号。
- [ ] 业务评审版无异常场景与边界条件小节、无权限小节、无验收标准小节；必要角色说明使用自然语言。
- [ ] 业务版功能名称下方的系统行为仅描述本次修改、调整的增量变化，未写入“其他非目标任务/模块维持原逻辑”、未改动历史前置步骤或“不新增××”等非变动内容；业务版未混入未变动的原有字段或设计稿/界面可直接看出的常规逻辑；确需输出“业务规则与生成逻辑”时仅描述前端仅展示结果字段/数据、后端有复杂计算或生成的逻辑；开发版异常使用“如果发生……，系统会……”。
- [ ] 开发版MOD、FR、FR-xx-n、FLD、TR、BR、EX、RM、AC编号稳定、唯一，全部引用可解析，无示意占位ID。
- [ ] `MOD/FR → FLD/TR → BR/EX → AC`追溯链闭合，没有为凑编号凭空增加条目。
- [ ] 共享规则注明适用范围，引用可定位；业务版使用功能/规则名称而非技术编号。
- [ ] 开发版每条BR都有校验层级（双端 / 仅后端；未决写待确认）。
- [ ] 开发版每条EX都有数据影响（整体回滚 / 部分成功 / 只读保留；未决写待确认）。
- [ ] 开发版每功能在异常小节之后依次包含权限与验收标准小节。
- [ ] 每条RM写清角色、操作可用/仅查看/不可见和数据范围；未决项不预设放行。
- [ ] 每功能保留“所有权限在服务端接口层强制校验，前端仅做展示控制”声明。

## Gate 5：开发版验收可执行

- [ ] 每条AC采用Given-When-Then，并引用所属FR及适用BR/EX。
- [ ] 每条AC包含具体数字示例与可观察结果，不仅写“符合预期”“正常展示”或“函数已调用”。
- [ ] 涉及计算时例子包含具体输入、统计口径、计算过程和预期显示值；精度/舍入有依据。
- [ ] 非计算场景也有明确输入和数量结果，不凭空设定业务值。
- [ ] 所有已确认P0/P1决策有对应AC，覆盖适用的成功、失败、取消、重复提交及刷新/恢复行为。
- [ ] 权限、并发、历史、通知和数据影响等适用异常均有验收，未决规则未伪装成确定断言。

## Gate 6：设计稿与DOCX交付

- [ ] 图片置于所属功能“设计稿：”引导行下，每张图紧跟同层级的一行图注。
- [ ] 存量页面局部改动的设计稿与真实系统的 Layout 壳子、菜单高亮及非改动区上下文一致，未误改或重排非本期存量区域。
- [ ] 位于中下屏、抽屉/弹窗或悬浮交互态的改动点已通过滚动聚焦、元素级截取或预交互准确入镜，无首屏截断目标区域或焦点偏离。
- [ ] 缺图原位写“待确认：尚未提供设计稿”，未伪造设计或静默跳过失效资源。
- [ ] DOCX图片使用可访问本地PNG/JPEG资源，相对路径基于源稿目录，图片未变成路径文本或外链。
- [ ] 两份DOCX都能被`python-docx`重新打开，且`py -m zipfile -t <file.docx>`通过。
- [ ] 首段为标题、次段为模块，无额外封面分页、TOC域、元信息段或表格。
- [ ] 逐段核验文字、混合加粗、真实列表层级及`●/○/■/■/■`编号定义，不只检查关键词存在。
- [ ] 段落、图片数量与源稿相符，`validate_prd_delivery.py` 校验通过（含UI设计稿时 `word/media/` 图片SHA-256哈希及 `ui-manifest.json` 需求/AC关联均核验通过）。
- [ ] 环境允许时已预览五级缩进、字体、分页、图片图注及版心；无法视觉检查时如实说明。
- [ ] 用户仅要求Markdown时已交付双版Markdown，不错误宣称生成DOCX；临时文件已清理。

## Gate 7：产品表达与去重

- [ ] 功能按独立用户目标划分，未把字段、校验、保存刷新或后台副作用机械拆成独立功能。
- [ ] 功能名、场景和描述各司其职；描述一句话概括能力，未串列全部条件、规则与异常。
- [ ] 简单行为一句话说清，无凑条数、各功能等长或重复概括；复杂前提、例外及范围仍完整。
- [ ] 行为、字段、流转、规则、异常各有独有信息；字段未展开流程，异常未重讲正常成功路径。
- [ ] 阈值、候选范围、锁定条件、汇总公式等在最合适位置只完整定义一次，跨小节/功能使用必要的短引用。
- [ ] 共享引用均可定位且不会造成理解断裂，未把全部正文变成引用列表；AC用具体样例验证而非复制规则全文。
- [ ] 业务版已省略无界面变更的字段小节与界面可见逻辑的规则小节，无“本功能不新增字段”等凑数话；开发版无无关技术实现、代码排查过程、通用工程口号或为填模板编造的计算/编号规则。
- [ ] 边界清单仅用于检查，未逐功能复制加载、失败、权限等通用段落；适用且会改变业务结果的处理仍有定义。
- [ ] 业务版先形成产品叙述，开发版只补必要对接信息；两版一致性按业务含义而非逐字一致检查。
- [ ] 已做逐条删除测试：删去不丢独有信息的内容已删除或合并，不同条件与恢复方式没有误合并。
- [ ] 精简旧稿时已另存文件，核对已确认决策及AC覆盖、稳定ID和图片关联；正文长度按相同口径对比，未以删规则、删验收或缩图代替精简。
- [ ] 仅文字变化时复用原型与截图，明确本次未重跑浏览器检查；DOCX重新生成并校验。

## 阻断条件

以下任一项成立，不得声称完整合规交付：

- 只交付一版、两版业务含义不一致，或擅自改变固定结构。
- 正文存在封面、目录、独立章节、宽表、问卷或集中未决问题。
- 开发版缺异常、权限或AC，业务版混入技术编号或异常、权限、AC小节。
- BR缺校验层级、EX缺数据影响、AC缺Given-When-Then/具体数字/有效引用。
- 权限不明却默认放行，或只描述前端可见性而没有服务端强制校验。
- 图片缺失、图注缺失、列表扁平化或加粗不符合模板。
- 同一关键事实在多个小节/功能完整重复，简单功能靠无关说明凑篇幅，或以精简为由删去已确认条件、权限、回退或验收覆盖。
- 要求DOCX却未验证可打开性与包结构，或以Markdown替代而不说明阻塞。

P0未决的同构双版只能作为待确认稿交付，不得标记正式定稿；未决属性必须明确标注，不能以空白绕过门禁。
