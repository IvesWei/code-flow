# PRD质量检查清单

## Gate 1：输入与范围

- [ ] 目标版本、主题和交付格式明确。
- [ ] 已阅读全部需求附件，包含图片说明、删除线、批注和链接上下文。
- [ ] 已确认旧版PRD是结构参考还是需求基线。
- [ ] 已定义本期范围和非本期范围。
- [ ] 文档元信息按用户要求处理。

## Gate 2：代码现状证据

- [ ] 已定位菜单/路由。
- [ ] 已定位主要页面和表单。
- [ ] 已定位API和类型。
- [ ] 已定位权限和操作者判断。
- [ ] 已定位状态流转与通知。
- [ ] 已定位目标集成模块。
- [ ] “当前现状”与“目标需求”在文档中明确分离。

## Gate 3：澄清完整性

- [ ] 数据对象粒度明确。
- [ ] 业务唯一键及归一规则明确。
- [ ] 角色、节点和职责明确。
- [ ] 保存、提交、完成、回退机制明确。
- [ ] 字段责任与条件必填明确。
- [ ] 实时引用或快照策略明确。
- [ ] 导入覆盖、追加或拒绝策略明确。
- [ ] 非法数据是整批失败还是部分成功明确。
- [ ] 引用后删除/停用策略明确。
- [ ] 无数据、部分匹配和冲突匹配行为明确。
- [ ] 原文矛盾和删除线内容已确认。
- [ ] 不存在未解决P0问题。

## Gate 4：功能闭环

- [ ] 每个模块有入口、角色和页面能力。
- [ ] 字段表包含类型、必填、来源、责任人和校验。
- [ ] 状态机包含执行人、动作、前置校验、目标状态和通知。
- [ ] 权限同时覆盖前端和后端。
- [ ] 通知包含事件、接收人、渠道、模板要素和失败策略。
- [ ] 数据关系包含稳定ID、业务唯一键和引用关系。
- [ ] 版本、快照和审计规则明确。
- [ ] 迁移、兼容、灰度和回退可执行。

## Gate 5：边界场景

- [ ] 大小写、空格、重复和组合唯一。
- [ ] 并发新增和并发编辑。
- [ ] 草稿、撤回、打回、转交和离职。
- [ ] 被引用记录的修改、停用和删除。
- [ ] 空文件、错模板、非法类型、缺字段、重复导入。
- [ ] 部分成功、错误报告、幂等重试。
- [ ] 零匹配、部分匹配、多匹配和冲突选择。
- [ ] 源数据变更对历史任务的影响。
- [ ] 通知去重、失败、重试和无权限深链。
- [ ] 大数据量、超长值、特殊字符和分页性能。
- [ ] 旧数据异常、迁移幂等和回滚。

## Gate 6：验收可测试性

- [ ] 所有P0/P1决策有对应AC编号。
- [ ] 每条AC包含触发场景和明确结果。
- [ ] 覆盖正常路径、失败路径、权限、并发、历史和通知。
- [ ] 没有仅写“符合预期”“正常展示”的模糊结果。
- [ ] 非功能指标有数值或可配置上限。

## Gate 7：DOCX交付

- [ ] 文件可由`python-docx`重新打开。
- [ ] `py -m zipfile -t <file.docx>`通过。
- [ ] 段落和表格单元格均纳入关键词检查。
- [ ] 核心章节、P0决策和验收标准存在。
- [ ] 文件大小、段落数和表格数非异常。
- [ ] 目录域、页眉、页脚和页码存在。
- [ ] 环境允许时已视觉预览，检查分页和表格宽度。
- [ ] 已清理一次性脚本与临时文件。

## 阻断条件

以下任一项成立，不得标记为正式定稿：

- 存在未确认的P0问题。
- 需求原文与用户确认结果冲突但未采用最新答案。
- 关键状态没有进入或退出条件。
- 权限只描述“谁能看到”，未描述后端约束。
- 引用数据允许删除但未说明历史行为。
- 导入没有重复、失败和幂等策略。
- 跨任务关联没有实时/快照定义。
- DOCX未经过可打开性和包结构验证。
